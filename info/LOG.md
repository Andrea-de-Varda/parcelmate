# parcelmate — project log

This is the running record of everything done to this codebase: project structure, all issues found, every design decision, and a dated log of every edit. It exists so that the eventual paper's methods section can be reconstructed exactly. Update it whenever anything changes. (Kept separate from README.md, which belongs to the upstream repo; merge relevant parts there later if desired.)

## What the project does

parcelmate applies the methodology of fMRI functional connectivity analysis to the internals of a language model. Each hidden unit of an LLM (a single dimension of the residual stream at a given layer boundary) is treated as a voxel; its "timecourse" is its activation across tokens of naturalistic text. The pipeline: (1) **connectivity** — run a HuggingFace model (default GPT-2) over text from several domains (wikitext, bookcorpus, agnews, tldr17, codeparrot, plus `random` and `whitespace` baselines), extract per-unit timecourses, and compute the unit-by-unit Pearson correlation matrix, averaged (Fisher-z) over 4 independent ~100k-token samples; (2) **parcellation** — binarize the absolute connectivity at each unit's 90th percentile, PCA to 200 components, run MiniBatchKMeans (k=50) 100 times, align the runs with the Hungarian algorithm, and average into a soft parcellation (unit × network membership probabilities); (3) **subnetwork extraction** — keep networks that are reciprocal best matches across all domains (chained in alphabetical domain order) and average them into a "shared" (domain-general) parcellation; (4) **knockout** — clamp the units belonging to shared subnetworks to zero via `PerturbedModel`/`PerturbedLayer` wrappers and re-run the connectivity pipeline on the lesioned model; (5) **plots** — connectivity clustermaps, network heatmaps, and stability analyses (correlations of connectivity matrices across samples and domains). Everything is cached as HDF5 under `results/`, driven by `python -m parcelmate.bin.main <config.yml> -s <steps>`; `parcelmate/bin/make_jobs.py` generates SLURM scripts.

Method design decisions -- which pipeline steps are free choices rather than necessities, what the alternatives are, and why -- are recorded separately in [PARCELLATION_DESIGN.md](PARCELLATION_DESIGN.md). This file records bugs, fixes and the dated edit history.

**Current state (2026-09-21).** The paragraph above describes the inherited pipeline. Since then: units can be residual-stream dimensions or post-GELU MLP neurons (`unit_type`); parcellation has converged Lloyd, Ward, Ward-initialised Lloyd, spatial ICA and a block-model refinement with optional centring, on binarized, Fisher, sparsified or standardized profiles; and every arm is scored on within- and across-domain reliability (ARI) and fidelity (block-mean prediction of held-out |r|) against a null partition evaluated on the real data (Iterations 12-13). 55 arms are scored across eight score files (Iterations 13-21, [plots/](../plots/)); the dimensions they vary, and what each bought, are summarised in [METHOD_SELECTION.md](METHOD_SELECTION.md). Settled so far: across-domain fidelity against the null partition is the selection criterion (Iteration 16); residual-stream results are confounded by dimension chains, so the unit is MLP neurons (Iteration 18); on MLP units Lloyd consensus is far more reliable than Ward, and a block-model polish is the largest fidelity lever (Iteration 18). The last round (Iterations 19-20) settled the rest. The final pipeline is: sparsified standardized profiles, PCA-100, Lloyd with 200 restarts and Hungarian consensus, k = 100, fitted within a single domain. Andrea's constraint is that no clustering may pool connectomes across domains. The block-model polish and the co-association consensus were dropped because they cost reliability. The confirmation run of that exact combination passed its pre-registered rule (Iteration 21): within-domain ARI 0.707, fidelities equal to the base. No further method tests are planned on GPT-2. Stage 1 (Iteration 22) applies the pipeline, on all MLP neurons rather than the 832-per-layer selection subsample, to eleven Pythia checkpoints at two sizes to ask whether the networks emerge over training; built and tested, not yet submitted.

The consequence is methodological: a whole-matrix baseline-vs-knockout comparison conflates the *mechanical* effect of the lesioned rows becoming degenerate with the *scientific* effect of reorganization among the surviving units. Measured in the integration run: r = 0.470 over the whole matrix versus r = 0.659 restricted to intact units. Pre-existing (zero-ablation has the same property) but only observable now that knockout runs. **Recommendation: restrict the knockout stability analysis to intact units, and mark all lesioned units NaN explicitly so downstream code excludes them deliberately rather than by accident.** OPEN — decision needed before knockout results are interpreted.

## Iteration 1 — basis and thread diagnostics (2026-09-07)

Run on the seven-domain `results/alldomains` connectivity matrices (GPT-2, local verification run) before committing to any downstream analysis. Motivation: the residual stream accumulates, `x_{l+1} = x_l + \Delta_l`, so unit *(l, j)* and unit *(l+1, j)* share content by construction. If cross-layer connectivity were dominated by this persistence, the parcellation would be recovering "residual threads" (one dimension tracked through depth) rather than functional networks. There is no brain analogue; it is purely architectural.

**Per-edge, the confound is large.** Mean |r| between the same dimension at adjacent layers, versus different dimensions at adjacent layers:

| domain | same *j* | different *j* | ratio | percentile rank of same-*j* |
|---|---|---|---|---|
| wikitext | 0.867 | 0.051 | 17.0 | 0.996 |
| agnews | 0.866 | 0.048 | 18.2 | 0.997 |
| tldr17 | 0.868 | 0.050 | 17.4 | 0.996 |
| bookcorpus | 0.863 | 0.069 | 12.6 | 0.993 |
| random | 0.894 | 0.053 | 16.9 | 0.998 |
| codeparrot | 0.849 | 0.168 | 5.0 | 0.974 |
| whitespace | 0.737 | 0.406 | 1.8 | 0.859 |

For a given unit, its correlation with its own dimension one layer up exceeds ~99.6% of its correlations with every other dimension one layer up.

**But it does not dominate the clustering signal, because threads are numerically tiny.** The parcellation clusters on a top-10% binarized fingerprint, which selects ~999 partners out of 9,983, while a unit has only 12 same-dimension thread-mates. Measured on wikitext:

| quantity | value |
|---|---|
| thread-mates captured in the top 10% | 11.17 of 12 (93.1%) |
| units capturing all 12 thread-mates | 54.4% |
| threads as a share of selected partners | 1.1% (11 of 999) |
| share of total \|r\| mass on same-dimension pairs | 1.50% (chance 0.12%, so 12x enriched) |

So the thread is almost always fully inside the fingerprint, and it is enriched an order of magnitude over chance, but 99% of the clustering signal comes from different-dimension partners. **Conclusion: the confound is real and must be reported, but it is not a reason to abandon the residual-stream unit definition or to switch to block writes (\Delta) now.** The planned rotation null (see Iteration 2) remains the decisive test, and its two-null variant (shared vs. per-layer rotation) will quantify the thread contribution directly.

**Side findings from the same diagnostic.** Off-diagonal correlation distributions differ qualitatively across domains:

| domain | kurtosis | mean \|r\| | p99 \|r\| |
|---|---|---|---|
| agnews | 25.9 | 0.044 | 0.156 |
| random | 22.5 | 0.050 | 0.177 |
| tldr17 | 22.2 | 0.046 | 0.167 |
| wikitext | 20.2 | 0.047 | 0.170 |
| bookcorpus | 6.5 | 0.065 | 0.235 |
| codeparrot | 0.3 | 0.160 | 0.549 |
| whitespace | -0.8 | 0.373 | 0.915 |

Three things follow. First, `whitespace` is **degenerate**, not merely different: mean |r| is 0.37 and the distribution is platykurtic, meaning nearly everything correlates with nearly everything. This is independent empirical support for excluding it from the domain-general criterion (M6). Second, `codeparrot` is a genuine intermediate case and should not be assumed comparable to the prose domains. Third, `random` is statistically indistinguishable from the prose domains (kurtosis 22.5, mean 0.050), which is direct empirical confirmation of **S6**: the decode/re-encode round trip leaves the "random" baseline far more language-like than uniform random token ids would be.

## Iteration 4 -- reliability and fidelity metrics (2026-09-09)

**Process failure worth recording.** Iterations 3 and the storage refactor built the machinery for the reliability/fidelity experiment -- the circular-shift null, three named variants, provenance -- but never implemented **either metric**. No ARI, no R2, nothing in `parcelmate/bin/` but `main.py` and `make_jobs.py`. Worse, `PARCELLATION_DESIGN.md` contained the word "fidelity" zero times: the metric design agreed in discussion existed only in chat, which is exactly the failure this log exists to prevent. Both halves are now fixed -- the metrics are implemented and tested, and the evaluation protocol is written up as PARCELLATION_DESIGN.md section 6.

- 2026-09-09 -- [parcelmate/metrics.py](../parcelmate/metrics.py) (new), [parcelmate/bin/score.py](../parcelmate/bin/score.py) (new) -- **both metrics implemented.** `reliability` is the adjusted Rand index between argmax labels of two parcellations fit on disjoint halves. `fidelity` fits a partition on half A, estimates each block's mean connectivity **on half A**, predicts half B, and scores R2 over the strict upper triangle -- so both the partition and the values are out of sample. `fidelity_ceiling` predicts half B from half A directly with no parcellation. `triviality` reports AMI against layer index and hubness decile. `score.py` walks the real and null trees, writes a tidy CSV, and prints a null-calibrated summary with domains weighted equally.
- 2026-09-09 -- **Bug caught by the tests, not by inspection.** The first `block_means` used `onehot.T @ onehot` for the pair counts, which is `diag(n)` rather than `outer(n, n)` -- so every off-diagonal block got count zero and the predictions were nonsense (R2 around -150 for a degenerate partition, -2141 for a good one). Fixed to `outer(sizes, sizes) - diag(sizes)`, which also excludes the `R[i, i]` self-pairs so the block means match the strict-upper-triangle scoring. Without the known-answer checks this would have produced plausible-looking rank orderings over arms and been very hard to spot.
- 2026-09-09 -- **The uncompressed reference is not a strict upper bound**, and the exception is informative. It carries all of the fitting half's noise into the prediction, whereas a block model averages that noise away, so a parcellation can beat it when the structure genuinely is block-like and the estimates noisy. Demonstrated both directions on synthetic data (a perfect 5-block partition scores 0.991 against a reference of 0.983; a partition too coarse for 25-block data falls below it). On real connectivity the reference should sit above every variant; a variant exceeding it would be a finding, not a bug. Documented in the docstring and in section 6.
- 2026-09-09 -- [parcelmate/model.py](../parcelmate/model.py), [parcelmate/constants.py](../parcelmate/constants.py), [parcelmate/bin/main.py](../parcelmate/bin/main.py) -- **split halves are now first-class cached artefacts**, not in-memory temporaries. `run_split_halves` Fisher-averages samples 1..n/2 and n/2+1..n into `connectivity_<domain>_halfA.h5` / `halfB.h5`, recording which samples each came from; `INPUT_NAME_RE` and `HALF_NAMES` were extended to match; `run_parcellation` parcellates `avg` plus both halves by default via `parcellate_keys`. So the ordinary parcellation step consumes them, they are cached, and every parcellation of a half carries the usual provenance. `main.py` gained a `split_halves` step and now runs **both** the real and null trees through split-halves and parcellation, since the null is only useful if the identical pipeline runs on it.
- 2026-09-09 -- [tests/verify_iter4_metrics.py](../tests/verify_iter4_metrics.py) (new) -- 24 checks, written to confirm the metrics fail in the *right directions* rather than merely run. The load-bearing one: a data-independent partition (labels fixed by position) scores ARI = 1.000 and R2 = 0.0004, which is the whole argument for why reliability cannot be used alone. Also verifies both metrics collapse on a circshift null, that block means come from the fitting half (a peeking implementation would score better and is detectable), and that a layer-driven partition is caught by the triviality check. 152 checks now pass across five suites, plus 13 pytest cases.
- 2026-09-09 -- [tests/verify_iter4_metrics.py](../tests/verify_iter4_metrics.py) -- added a **full-pipeline integration test**: builds a small real tree and a circshift null tree with per-sample connectivity for two domains, runs `run_split_halves` and `run_parcellation` for two variants on *both* trees, then scores them with `score_tree` and `summarize`. Verifies every metric is produced, the uncompressed reference gets its own row, across-domain rows use different fit/eval domains, and real data beats its own null on fidelity (mean delta 0.926). Synthetic and small deliberately: a GPT-2-scale integration run writes ~400 MB per matrix and exhausted the 16 GB local scratchpad at 9 GB, so the real integration happens on the cluster where the data already lives.
- 2026-09-09 -- [info/PARCELLATION_DESIGN.md](PARCELLATION_DESIGN.md) -- new **section 6, "How we decide whether a change is an improvement"**: the two metrics and why they are degenerate in opposite directions, the null calibration for both, the uncompressed reference and its caveat, the triviality checks, and the settled protocol choices (halves as samples 1,2 vs 3,4; block means on the fitting half; domains weighted equally; hard argmax as headline with soft reported alongside). Sections 6-11 renumbered to 7-12.

## Iteration 5 -- audit, two ceilings, and a stability finding (2026-09-09)

An audit of the Iteration 4 code against the agreed design found no correctness bugs in the metric math -- fidelity does not peek at the held-out matrix, and a test would catch it if it did -- but four things that would have bitten, plus a set of smaller inconsistencies. It also turned up an empirical result that matters more than any of them.

**The finding.** Measured on real wikitext connectivity (k=20, 3,000-unit subsample, 40 restarts), the two arms differ by nearly an order of magnitude in how reproducible their parcellations are across seeds *on identical data*:

| arm | ARI across seeds, same data | median max membership | units above 0.5 | networks each unit spreads over |
|---|---|---|---|---|
| `current` (binarize + PCA 200) | 0.096 | 0.20 | 1.6% | 11.5 of 20 |
| `nopca_fisher` | 0.741 | 0.53 | 51.6% | 4.1 of 20 |

Three consequences. First, raw cross-half reliability is **not comparable between arms** without dividing through by each arm's own noise floor -- an arm could look more reliable purely by having a quieter algorithm. That turned the reliability ceiling from a nice-to-have into a requirement. Second, the viability of a hard argmax label is **arm-dependent**: at a median max membership of 0.20 (uniform is 0.05) the `current` label is the top of a nearly flat noisy vector, while `nopca_fisher` puts half its units above 0.5. Third, `current` is *not* collapsing -- it uses all 20 clusters with the largest at 19-22%, so it produces a balanced partition that simply is not stable under discretization.

**Restart scaling and where the instability lives.** For `current`, going from 20 to 60 restarts roughly doubles hard ARI (0.063 -> 0.146), and at both budgets the *soft* consensus agrees 4-5x better than its argmax (0.303 and 0.457). So the underlying consensus is substantially more reproducible than the discrete labels derived from it. This is the mechanism behind the low peakedness, and it is the caveat attached to the decision to run 20 restarts: at that budget `current`'s reliability is not meaningfully distinguishable from zero, and the honest reading is "this pipeline does not produce a reproducible discrete parcellation at this budget" rather than "reliability is 0.06".

**Costs, measured rather than guessed.** At full scale (9,984 units, k=50): one k-means restart takes 44.5 s for the no-PCA arm and 6.2 s for the PCA arms. At the configured 100 restarts that is ~68 h serial for 42 matrices, which nobody had estimated and which would have been submitted under a 12 h wall clock. The nulls are exactly half of any such budget, and the across-domain (`avg`) matrices are a third of it. Both ceilings are free: the fidelity ceiling is one R2 between two matrices, and the reliability ceiling costs two Hungarian alignments, measured at 0.1% of the k-means time (0.04 s against 45 s).

## Iteration 6 -- first scored results, and what they show (2026-09-10)

Jobs 17356343 (split_halves + parcellation) and 17356344 (score) both completed clean: 1 h 39 m and 34 m, peak RSS 4.2 and 4.4 GB against 64/96 GB requested, 224 HDF5 files, 938 scored measurements. My wall-time estimate of ~14 h was out by 8.5x, because the earlier 44.5 s-per-restart timing was effectively single-threaded and the job ran on 16 cores.

**The connectome result replicates, and slightly exceeds, the poster.** Per-domain fidelity ceiling (R2 of half A predicting half B): agnews 0.985, bookcorpus 0.993, random 0.994, tldr17 0.978, wikitext 0.980, whitespace 1.000, codeparrot 0.749. For two symmetric noisy estimates of one truth, R2 = 2r - 1, so a ceiling of 0.98 implies a connectome correlation of about **0.99**, against the 0.974 Cory's poster reports. Higher as expected, since our halves are ~197k tokens against their 50k. Our between-domain figure, computed separately on `results/alldomains`, was 0.313 excluding whitespace against their 0.369. Both halves of their Result 1 reproduce.

**A bug in `fidelity_across`, now fixed.** Across-domain R2 came out at -11 to -13 for every arm and -118 for whitespace against agnews. The cause is scale, not structure: domains differ enormously in overall correlation magnitude (whitespace mean |r| 0.37, wikitext 0.047), so block means fitted on one domain are on the wrong scale for another and the residuals dwarf the variance. The ceiling itself was negative, which is the tell -- it is the raw matrix predicting the other raw matrix, with no parcellation involved. R2 asks whether the *values* transfer; the agreed question was whether the *structure* does. Now reported as Pearson r, which is scale-invariant. Demonstrated in the test suite: identical structure rescaled 8x and offset scores R2 = -597 and r = 1.000.

**The parcellations discard most of the reproducible structure.** Against a ceiling of ~0.98, held-out fidelity on genuine prose domains is 6-14%:

| domain | ceiling | current | legacy | nopca_fisher |
|---|---|---|---|---|

## Iteration 9 -- why the null beats real data, and a data-matched across-domain metric (2026-09-10)

**The question.** Across the five arms the circular-shift null very often scores *higher* than the real data, not merely as high. `nopca_fisher`: fidelity r 0.390 real against 0.748 null. `legacy`: reliability 0.471 real against 0.573 null. A null that ties makes sense; a null that wins by a factor looks like a bug.

**It is not a bug.** The inversion is reproduced from first principles in [analysis/null_mechanism.py](../analysis/null_mechanism.py), on 300 simulated units with no access to the real connectomes:

| data | standardize | mean abs r | SS_tot | block R2 | ARI across halves | AMI with hubness |
|---|---|---|---|---|---|---|
| null-like (no true structure) | no | 0.020 | 27.6 | **0.149** | **0.406** | 0.419 |
| null-like | yes | 0.020 | 27.6 | 0.033 | 0.001 | 0.032 |
| real-like (strong continuous structure) | no | 0.099 | 532.1 | **0.027** | **0.080** | 0.017 |
| real-like | yes | 0.099 | 532.1 | 0.032 | 0.115 | 0.033 |

Data with *zero* cross-unit structure scores 0.149 block R2 and 0.406 split-half ARI; data with strong real structure scores 0.027 and 0.080. Both inversions, from the same generator, with the fix (standardizing) restoring the correct ordering on both.

**Three facts compound.** (1) A circular shift preserves each unit's autocorrelation, and two independent series with autocorrelations tau_i, tau_j have sampling correlation of size ~sqrt(tau_i tau_j / T) -- a separable, rank-one pattern. (2) The pipeline takes `|r|`, and for uncorrelated units the correlations are zero-mean noise, so E|r_ij| = sqrt(2/pi) sigma_ij: **the absolute value converts zero-mean noise into a positive mean field with exactly that rank-one shape.** The null connectome is not structureless, it is dominated by a clean outer product of per-unit connection strength. (3) A rank-one matrix is the most block-friendly object there is -- sort by strength and a block model reproduces it almost exactly -- while the real connectome's structure is continuous, graded and high-dimensional, which 50 blocks cannot express.

**The key point is that R2 is a ratio.** What matters is not how much structure is present but what fraction of it the model class can reach. In the simulation the real data has 19x the variance to explain (SS_tot 532 vs 28) and the block model reaches almost none of it; the null has very little variance and nearly all of it is reachable. Hence real 0.027 against null 0.149 with the signal running entirely the other way.

The same three facts explain the reliability inversion, which is otherwise the stranger half. Per-unit autocorrelation is a *fixed property of the unit* -- identical in half A and half B, and largely identical across domains, since it is a property of the model rather than of the text. So "sort units by connection strength" is an extremely reproducible partition, and the null earns a high ARI for reliably re-describing a constant. Real continuous structure gives k-means no stable basin and it earns a low one. This is also why the cross-domain nulls are so high: the artifact transfers across domains perfectly, because it never depended on the text.

**Consequences.** (a) Nothing here is a defect in the null -- the circular shift does exactly what it was specified to do. The defect is in the *pipeline*, which was reading a quantity (per-unit magnitude) that the null preserves. (b) `|r|` is not innocent: on near-zero correlations it manufactures the artifact rather than merely passing it through. This was previously logged as a settled decision (2026-09-08, keep `|r|` because a deactivation is a real fMRI signal), and it should be revisited now that its interaction with the null is understood -- signed r with a Fisher transform would not produce a positive mean field from noise. (c) The result that survives all of this is unchanged and is now better motivated: `vmf_profile` standardizes the rank-one field away, and is the only arm whose within-domain scores are not dominated by the artifact.

**Second look at the diagnosis (same day, Fable).** Ablations added to [analysis/null_mechanism.py](../analysis/null_mechanism.py). *Both ingredients are necessary*: with signed r instead of `|r|` the structureless data's block R2 falls 0.121 -> 0.027 and its split-half ARI 0.197 -> 0.017; with homogeneous autocorrelation they fall to 0.013 and 0.008. So the inversion is not "autocorrelation" or "absolute value" alone but their product, and the recommendation to revisit `|r|` is strengthened. *"Rank-one" is approximate*: Bartlett gives Var(r_ij) ~ <rho_i, rho_j>/T, a Gram matrix of autocorrelation functions, rank-one only when the ACFs form a one-parameter family. *The diagnosis was incomplete in one respect.* On real data `vmf_profile`'s null still has reliability 0.289 with AMI-hubness 0.069 and AMI-layer 0.050, so something reproducible survives standardizing that is neither magnitude nor layer; the one-parameter ACF-shape simulation collapses to ARI 0.000 under standardizing and does not account for it. Units sharing a distinctive spectral signature do: a periodic component keeps its period under a circular shift, and |cos| of a random phase difference averages 2/pi, so such units stay mutually correlated in `|r|` whatever their phases -- a pattern over units rather than a row scale, which z-scoring cannot remove and which reproduces across halves (simulated: ARI 0.119 after standardizing, AMI with family 0.464). This is exactly the per-unit temporal structure the circular shift is specified to preserve, so its appearing in the null and being subtracted is the null doing its job, not a defect. The simulation is qualitative, not calibrated: its real-like block R2 is 0.03 against 0.117 in the data and its spectral families are far stronger than GPT-2's. Checked and not the cause: the shift offsets are seeded per (domain, sample) via `derive_seed(seed, 'null', domain, i)`, so no shift pattern is shared between halves or domains.

**Three pipeline-health findings from the same pass**, none a bug in the scoring, all previously unlogged. (1) `nopca_fisher` has only **27.75 of 50 networks non-empty** on real prose (argmax leaves ~22 clusters with no units); its 0.698 reliability and its fidelity are those of a ~28-block solution, not a 50-block one, which also confounds the fidelity comparison with the other arms. (2) `current` has median max-membership **0.20 at k = 50**: the consensus is nearly flat and the argmax label is the top of a noisy vector, which is why its reliability is 0.111 -- the binarize+PCA path barely converges to anything. (3) The restart-split ceiling reads 0.42-0.64 rather than ~1, i.e. two 10-restart consensuses of the *same data* agree at ARI 0.42 for `vmf_profile`. The honest reading is not "pessimistic proxy" but that **consensus clustering is far from converged at 10 restarts, and probably at 20**, so the reliability numbers are partly limited by k-means instability rather than by data. Either restarts go up (20 -> 40 doubles the parcellation stage, ~14 h -> ~28 h serial) or the instability is reported as a limit. Also verified: CSV counts match real vs null for every metric, no NaN/inf, within rows have fit == eval and across rows fit != eval, and R2 ~ r^2 for every arm (0.117 vs 0.340^2 = 0.116), so the block-mean predictions are calibrated.

## Iteration 10 -- surrogate normalization: making the null a floor again (2026-09-10)

**The problem, in one line.** `|r|` of a near-zero correlation is not near zero: E|r_ij| = sqrt(2/pi) sigma_ij, so the absolute value converts noise into a positive number whose size is that pair's noise level. sigma_ij depends on the two units' autocorrelations, a circular shift preserves autocorrelation exactly, and the resulting field is both separable (maximally block-fittable) and a fixed property of each unit (maximally reproducible). The null therefore contained precisely what both metrics reward, and out-scored real data on four of five arms. See Iteration 9 and [analysis/null_mechanism.py](../analysis/null_mechanism.py).

**The fix.** `run_connectivity(n_surrogates=K)` draws K further circular shifts per sample, under a different seed key from the scored null, and stores the per-pair second moment of the resulting correlations as `surrogate_var`. Everything downstream divides by sqrt of it, so the matrix that gets clustered and scored is |z_ij| = |r_ij| / sigma_ij rather than |r_ij|. Then E|z_ij| is the *same constant for every pair*: the field is gone, a block model has nothing to fit, and k-means has no per-unit magnitude to sort by. The null becomes an actual noise floor and real-minus-null becomes readable.

Verified on data where the truth is known -- units with heterogeneous autocorrelation and zero cross-unit structure ([tests/verify_iter6_surrogate_norm.py](../tests/verify_iter6_surrogate_norm.py)): the correlation between a unit's mean connectivity and its autocorrelation falls from **0.91 to 0.05**, the relative spread of per-unit strength from 0.180 to 0.066, and the R2 of a hubness-sorted block model from **0.122 to 0.020**.

**Design decisions.**

- *Empirical surrogates, not the analytic Bartlett variance.* Bartlett's Var(r_ij) ~ <rho_i, rho_j>/T assumes Gaussianity and stationarity, which GPT-2 activations violate (heavy tails, BOS spikes). K=32 costs 32 correlation matmuls per sample and the forward passes -- which dominate the step -- are reused.
- *K=32.* Relative error per entry is ~1/sqrt(2K) = 12%. That error is independent across pairs, so it costs a little power but, unlike the artifact it replaces, cannot manufacture a coherent field.
- *The variance estimate is held out from the scored null.* Surrogates use `derive_seed(seed, 'surrogate', ...)` where the scored null uses `derive_seed(seed, 'null', ...)`. Normalizing the null by variances it contributed to would whiten it with its own noise and push it below zero artificially.
- *The same variances normalize both trees.* Different denominators would make every real-minus-null difference partly a difference of scalings.
- *`|z|`, not signed z.* The 2026-09-08 decision to keep `|r|` (a deactivation is a real signal) is preserved: what was wrong was never the absolute value as such, but taking it of a quantity whose noise scale varied by pair. Normalizing first removes the harm and keeps the semantics.
- *Detection is by presence of `surrogate_var`, not by a config flag.* A boolean needing to be set identically in the parcellation and the scoring config is exactly the failure this project already paid for (S10). A tree either carries the variances or it does not, and one shared function, `util.surrogate_normalized`, is the only place `|r|` is formed -- called by both `run_parcellation` and `score.load_connectivity`.
- *A half's variance is the 2-sample average, larger than the avg file's 4-sample one.* Propagated through `split_halves` via Var(mean of m independent) = sum/m^2, valid because arctanh(r) = r + O(r^3) and null correlations are small by construction. Applied only to null variances, never to the real correlations. A partial set of variances raises rather than averaging with the wrong denominator.

**Expected side effect on finding 1 (the `nopca_fisher` cluster collapse).** Empty clusters there came from hub units with large profile norms capturing centroids; normalization removes the norm disparity at source, so the arm should fill closer to 50 networks without any change to the clustering code. If it does not, the collapse has a second cause and needs its own fix.

**What this does NOT remove.** The separable field only. Units sharing a distinctive spectral signature stay mutually correlated in `|z|` (Iteration 9), though per-pair sigma absorbs much of it since <rho_i, rho_j> includes the periodic components. Also a real change of meaning: z upweights pairs of fast-varying units, whose correlations are better estimated. That is the correct treatment of an effect size, but it is a different connectome from the one in Iteration 8, not a cleaned-up version of it.

**S11 -- found on review before the parcellation step ran, not after.** The three Fisher arms would have been silently destroyed on the normalized tree. `fisher()` multiplies by (1 - eps) and then takes arctanh, so an input of 15 -- a typical real |z|, since |r| ~ 0.05 over sigma ~ 0.005 -- becomes arctanh(0.999) = 3.8 with no error and the `isfinite` assert never fires. Every real entry above 1 would have collapsed to the same constant: three of five arms binarized at |z| > 1, a full column of plausible numbers, nothing raised. **FIXED**: `sample_parcellations` now asserts its Fisher input is a correlation matrix (max <= 1), so any route to that branch with an effect size is loud; `run_parcellation` switches the transform off when the tree carries `surrogate_var`, because |z| is already variance-stabilized and arctanh of it is neither needed nor defined; and the provenance records both the configured `fisher_transform` and `fisher_transform_applied` plus `input_normalized`, so the two experiments' arms line up by name while the file says exactly what was done. Four checks added. The binarize arms are unaffected -- a row-wise quantile is invariant to the monotone arctanh -- and so is the scorer, which never applied the transform.

**Pre-registered success criteria for the run**, so the result is read against something written down first. On the null tree, prose domains, all arms: (i) in-sample block fidelity near 0 (it was 0.17-0.57), (ii) AMI between the null parcellation and hubness decile near 0 (it was 0.07-0.34), (iii) the relative spread of per-unit strength in the null |z| matrix small (the analogous quantity fell 0.180 -> 0.066 in simulation). On the real tree: `nopca_fisher` filling closer to 50 networks than 28. If (i)-(iii) hold and real-minus-null is still not positive, the parcellations are the problem, not the metric. One residual is expected and should be reported rather than explained away: E|z| = sqrt(2/pi) only for Gaussian z, and a heavy-tailed unit (massive activations, BOS spikes) has a lower E|z| at the same variance, so a weak *inverted* strength field can survive for a handful of units. Its size is what (ii) and (iii) measure.

**Timing, measured.** 320 s per sample against 43 s unnormalized, i.e. ~8.7 s per surrogate for a 9,984 x 98,304 shift plus correlation on an a6000; 28 samples, ~2.5 h total, within the 8 h requested.

**Measured on the first written sample (wikitext, 400-row slice), and it is the decisive check.** On the NULL tree the field is gone exactly as designed: mean |z| = 0.824 against the theoretical sqrt(2/pi) = 0.798, and the relative spread of per-unit strength falls from **1.160 to 0.018**, a 64-fold flattening. (The correlation between a unit's noise scale and its strength stays high at +0.85, but correlation measures direction, not size; an ordering with 1.8% relative spread has nothing for a block model to fit or for k-means to sort by.) The null's advantage, which was the entire problem, is removed at the source.

**But normalization introduces a different confound on the REAL tree, and it must be reported, not buried.** There the relative spread of unit strength *rises* from 0.213 to 0.356 and its correlation with the unit noise scale from -0.32 to -0.80. The magnitude field is not removed on real data; it is inverted and strengthened. The reason is that sigma_ij spans a factor of 540 in GPT-2 (median 3.5e-3, max 0.68): a unit that is near-constant or dominated by a slow drift -- the massive-activation dimensions -- produces correlations of ~0.7 under a circular shift, so its real correlations are genuinely unmeasurable and its |z| is uniformly small. Dividing by sigma is the correct treatment of an effect size and this is the honest answer for those units, but it means a real parcellation can now score well by sorting units on **detectability**, which is a fixed property of the unit and therefore reproducible across halves and domains, while the null -- having no field left -- cannot match it. That would produce a positive real-minus-null for a reason that has nothing to do with connectivity: the same species of artifact as before, moved from the null side to the real side.

`triviality` therefore gains **`ami_noise_scale`**, the AMI between the parcellation and the per-unit noise-scale decile, exactly parallel to `ami_hubness`. Added before the parcellation ran, so the diagnostic exists in the same run as the result rather than being reconstructed afterwards. **Read the two together**: a genuine win needs real-minus-null positive AND `ami_noise_scale` low. If both `ami_hubness` and `ami_noise_scale` are near zero and real still beats null, the result is about connectivity.

**Run as a separate experiment.** [configs/reliability_norm.yml](../configs/superseded/reliability_norm.yml) is byte-identical to `reliability.yml` apart from `n_surrogates: 32` and `output_dir: results/reliability_norm`, so the comparison is controlled. The unnormalized tree stays on disk and the Iteration 8 numbers stay reproducible.

## Iteration 12 -- the null was being used the wrong way round (2026-09-11)

**Andrea's point, which supersedes Iterations 10-11 as the primary analysis.** Normalizing the connectivity (Iteration 10) made the null a floor, but it did so by changing the *data* -- |r|, the coupling strength we care about, became |z|, a test statistic -- when the flaw was in the *comparison*. We were scoring R^2(P_real on real B) against R^2(P_null on **null** B): two different target matrices, two different denominators. That is the entire reason a structureless matrix could out-score real data (Iteration 9), and it is not fixed by making the null matrix flatter; it is fixed by putting both partitions on the same target. Both (a) the real values differing between runs and (b) the residual null reliability in the no-PCA arms (Iteration 11) were symptoms of the same thing: the comparison was between two experiments, not between two partitions.

**The right null is the null partition on the real data.** Fit P on shifted half A (as before); estimate the block means on **real** half A; predict **real** half B. Same target, same SS_tot. real - pnull is then exactly *the credit the clustering earns beyond a partition that carries only per-unit properties* (autocorrelation, hubness, spectral signature -- everything a circular shift preserves). Hubness stops being an artifact to scrub out of the data and becomes what it should be: a **baseline** both partitions are credited for and only the real one is credited *beyond*. For reliability, ARI(P_null_A, P_real_B): how much more real A agrees with real B than shifted A does. A random partition of the same k (`rand`) is the third reference, so pnull's contribution above it is attributable to per-unit structure and not to block-model capacity -- a collapsed null partition filling 17 of 50 blocks has less capacity than a full one, and `triviality_n_effective_networks` under the pnull tree says how much.

**Reliability averages both orientations; fidelity cannot.** Andrea's formulation was `reliab(M_A, M_B_null)` where the implementation had `reliab(M_A_null, M_B)` -- the same estimand with the shift on the other half, and since ARI is symmetric and the halves are exchangeable, the difference between them is sampling noise. Neither is more correct, so both are computed and averaged: it halves the variance for free and removes an arbitrary choice of which half carries the shift. Fidelity is different and must NOT be symmetrized: the real row is directional (fit on half A, predict half B), so its reference has to keep that direction and differ only in the partition. The mirror, fitting on B to predict A, is a reference for a real quantity we do not compute. `rand` follows the same rule, with two independent draws for the reliability average, seeded by orientation. Because reliability now needs the null parcellation of BOTH halves, a tree missing one is refused rather than silently scored one-sided.

Two consequences. **It needs no normalization**: |r| returns as the primary connectome. **It needs no new data**: every piece existed on disk, and the cost is a CPU re-score. The block means *must* come from real A -- from shifted A they would be near-flat and R^2 ~ 0 trivially, which is a test that is checked ([tests/verify_iter7_partition_null.py](../tests/verify_iter7_partition_null.py)).

**|z| survives as a rung, not as the experiment.** `vmf_profile -> vmf_z` changes exactly one thing. On top of row-standardization, |z| does two things standardization cannot: sigma_ij ~ a_i a_j is a row *and* column scaling and standardizing removes only the row part, so |z| additionally reweights every profile by partner precision; and it divides out the non-separable spectral-family part of the null variance (Iteration 9). Whether that helps is now an attributable empirical question rather than a global choice.

**Cleanup, so that one design choice no longer means one experiment.** Normalization triggered by the *presence* of `surrogate_var` (Iteration 10) forced a second tree for the |z| question. It is now an explicit per-arm setting, `normalize: surrogate`, recorded in the parcellation's provenance and **read back from there by the scorer** -- the single source of truth, so the parcellation and the metric cannot disagree about the input (the S10 lesson, kept), and one tree holds |r| arms and |z| arms side by side. `util.connectivity_matrix(data, normalize)` is the one place |r| is formed. Ceilings are emitted per input mode (`(ceiling)`, `(ceiling:surrogate)`). One config, [configs/ladder.yml](../configs/ladder.yml), six arms; `reliability.yml` and `reliability_norm.yml` moved to `configs/superseded/` with a README saying what each produced. One tree, `results/ladder`, whose connectivity is hard-linked from `results/reliability_norm` (r plus `surrogate_var`; same inode, zero GPU, zero disk); halves, parcellations and scores regenerated there so every file's provenance is this config at one commit. The two earlier trees stay on disk as the record of Iterations 8 and 11.

**Pre-registered expectations for the run.** (i) `rand` fidelity and reliability ~0 for every arm. (ii) `pnull` fidelity clearly positive for the unstandardized arms on |r| -- that is the hubness baseline, now measured rather than confounded -- and near `rand` for `vmf_profile`, which divides magnitude out. (iii) `null` (pipeline on shifted data) continues to out-score `real` on |r| arms, and that is now correctly read as a property of the denominator, not of the parcellations. (iv) The ranking by real - pnull is the result. If it agrees with the |z| ranking from Iteration 11, the finding is robust to the normalization question; if it does not, the |z| rung says by how much.

Doing it now would mean plotting a file that does not exist.

**YOLO 1 -- make reliability measure data** ([configs/yolo.yml](../configs/yolo.yml), tree `results/yolo`, prose domains only, connectivity hard-linked from the ladder). `clustering: kmeans` is full Lloyd with k-means++ and one init per restart, 40 restarts (ceiling from two 20-restart consensuses); `vmf_lloyd` and `nopca_lloyd` are the ladder's two leading arms with this optimizer. `fisher_pca_lloyd` keeps PCA-200 but drops the whitening (`pca_whiten: false`), to see whether whitening was what flattened `current`/`fisher_pca`. `vmf_ward` is Ward agglomerative on the same standardized profiles: deterministic, one sample, the restart-split ceiling is 1 by construction, so its reliability is data alone; if it matches converged k-means the restarts can go, which is the largest efficiency win available. **YOLO 2 -- fit what you score.** `blockmodel` follows each Lloyd restart with `metrics.blockmodel_refine`: coordinate descent on the block-model SSE, on the raw |r| the scorer targets. For unit i and candidate block c the error sum_{j != i} (r_ij - m_{c,c(j)})^2 expands to sum_b [-2 m_cb S_ib + n_b^(i) m_cb^2] plus a term independent of c, so a sweep is a few n x k products; all units move at once, the SSE is tracked per sweep and the best labeling is returned (batch updates on a symmetric objective can overshoot). This gives the attainable block fidelity at each k, the top of the axis as pnull is the bottom, and a partition whose objective is the metric. The scientific risk is that block means reward hubness sorting; pnull, rand and `ami_hubness` are the instruments that will show it, and if fidelity-optimal partitions are hubness partitions then fidelity alone cannot be the selection criterion. `vmf_lloyd100`, `vmf_ward100`, `blockmodel100` repeat the three families at k = 100, each parcellated on the null tree too, so every k has its matched `pnull`.

## Iteration 15 -- YOLO 4, the MRI bundle: spatial ICA and the sparsification rungs (2026-09-12)

Built while the YOLO 2 block-model arms finish. Own tree (`results/yolo4`, connectivity hard-linked from `results/yolo`), so the queued YOLO 1+2 score job -- which scores every variant of `configs/yolo.yml` and refuses partial tables -- is untouched. Config: [configs/yolo4.yml](../configs/yolo4.yml). Andrea's design brief for the ICA arm is followed point by point; what the implementation taught us is below.

**Spatial ICA from the correlation matrix, exactly.** MELODIC's spatial ICA is PCA of the token x unit matrix followed by FastICA on the k whitened spatial maps with units as samples. The whitened spatial PCs are the top-k eigenvectors of the unit x unit correlation matrix scaled by sqrt(n_units), which we already store signed; verified on synthetic data that the k-dimensional subspace is identical to the one from the SVD of the activations (projection matrices equal to 1e-8). So `clustering: ica` costs one `scipy.linalg.eigh` on the 9,984 x 9,984 signed matrix per connectivity file (top-k only, ~1-2 min) plus 40 FastICA restarts on a 9,984 x k array, and stores no activations. Per restart: FastICA (`whiten='unit-variance'`, fresh random unmixing init from the shared RNG), each map's sign fixed so its skew over units is positive, maps z-scored, winner-take-all over components for the hard labels. Labels go through the same alignment and consensus as k-means, so ICA and clustering are treated identically downstream; the z-scored maps additionally go through the same Hungarian alignment (`_align_samples` now accepts a 3-D array of soft maps) and their consensus is stored as `ica_maps`. `metrics.map_reliability` (mean correlation between Hungarian-matched maps of the two halves, matched on plain correlation so a sign flip counts as a loss) is scored as `reliability_within_maps` -- ICA judged on the soft object it actually produces, alongside the hard-label metrics every arm gets. Fidelity is scored on |r| as for every other arm; only the clustering input is signed. The arm asserts that binarization, Fisher, standardization, PCA and block-model refinement are all off, so it cannot be silently mis-stacked with the profile preprocessing.

**Three properties of ICA-with-WTA, found while building the test, that will matter when reading the run.** (1) *A partition is not an ICA model.* Mutually exclusive planted blocks give k indicator maps that sum to a constant, so after centering they span only k - 1 dimensions and one component is left holding the constant direction, which whitening inflates into noise; "one dominant source per unit" generators are the same thing softened. FastICA recovers such maps at r ~ 0.7 however the contrast is chosen, while k-means on the same eigen-subspace recovers the partition exactly. This is the known reason ICA-WTA and clustering agree only broadly (Yeo et al. 2011), now seen directly. (2) *Variance normalization couples sources.* Every correlation matrix divides each unit by its own variance, and so does MELODIC; if a unit's variance is dominated by its loadings, the normalized maps are dependent even when the raw ones were independent. Dense exponential maps: r = 0.99 recovered from the raw mixture, 0.6-0.85 after normalization. Sparse maps (30% of units per source) are recovered at 0.99 either way, because few units are dominated by a single source. Spatial ICA on a connectome therefore presumes sparse maps, which is also what fMRI assumes. (3) *FastICA needs kurtosis, not just skew.* Sparse 0/1 maps at 20% density (skew 1.5, excess kurtosis 0.25) are recovered at only 0.7 from an exact mixture with every contrast (`logcosh`, `exp`, `cube`, parallel or deflation); exponential-weighted sparse maps (kurtosis ~8) at 0.99. The arm is implemented as specified; these are reasons it may lose to clustering on the hard-label metrics, and `reliability_within_maps` is there so that a loss on labels is not mistaken for a failure of the maps.

**The sparsification rungs**, each one change from `fisher_pca_lloyd` in the YOLO 1 score (dense Fisher magnitudes, unwhitened PCA-200, 40 Lloyd restarts): `sparse_fisher_lloyd` keeps only the top-10% Fisher magnitudes per row (`sparsify_fisher: true`, the missing rung between binarizing and keeping the dense magnitudes); `binarize_row_lloyd` binarizes per row (the ladder's `current` with the converged optimizer and no whitening); `binarize_global_lloyd` binarizes with one threshold for the whole matrix (`binarize_scope: global`), so hubs keep more partners than weak units instead of every row being equalised to 10% -- the binarized twin of the `nopca_fisher` vs `vmf_profile` contrast, and the prediction from the hubness story is that it lands where `nopca_lloyd` did: better within domain, worse across. All three also at k = 100, and ICA at k = 100, each with its own matched null partition.

**Job shape.** Eight arms as parallel `john` jobs (`launch_yolo.sh generate4` links the connectivity and writes the scripts on scdt; `submit4` submits them and the score job on sc). ICA arms 6 h / 8 h; the PCA-200 arms are cheap (`fisher_pca_lloyd` took 24 min for all 24 matrices), 2-3 h requested. Expected: ICA ~10 min per matrix, so ~4 h; the rest under an hour; score ~2 h.

## Iteration 16 -- all 16 arms scored: the dissociation is systematic, and it decides the criterion (2026-09-13)

Everything launched over 11-12 September has completed. Prose means, Δp = real - pnull.

**The central result: hubness buys variance explained and reliability, and costs transfer.** Over the 16 arms of the two runs, corr(AMI with hubness, within-domain fidelity R2 Δp) = **+0.63**, corr(AMI with hubness, within-domain **reliability** Δp) = **+0.82**, and corr(AMI with hubness, across-domain fidelity r Δp) = **-0.70**. So within-domain reliability in particular is largely bought by sorting units on connection strength, and what buys it costs transfer. **Within-domain performance cannot be the selection criterion, and reliability least of all.**

**Correction to the first version of this entry (made 2026-09-13 while building the combined figures).** It also claimed that within-domain and across-domain fidelity are *uncorrelated* (-0.04), i.e. near-orthogonal objectives. That number compared within-domain **R2** against across-domain **r**, because R2 is not defined across domains (the two connectomes sit on different scales, LOG.md `agreement`). The comparison is therefore a measure mismatch, and the apparent orthogonality is an artifact of it. Like for like, r against r, within and across fidelity correlate **+0.64** over the 16 arms and **+0.59** over all 24. The measure difference is itself the mechanism: R2 rewards predicting the overall LEVEL of the connectivity, which a hubness partition does well, while r scores only the pattern -- corr(hubness, within R2 Δp) = +0.59 but corr(hubness, within **r** Δp) = **+0.10** over 24 arms. Hubness buys level, not pattern.

**What that correction changes, and what it does not.** The selection criterion stands and is if anything better supported: hubness still costs transfer (-0.60 over 24 arms), so an arm should not be chosen on within-domain numbers. What changes is the ranking under a like-for-like measure. On Pearson r the standardized family leads **both** within and across domain -- `vmf_ward100` is first on each (within Δp 0.325, across Δp 0.224), with `vmf_lloyd100` second within (0.321). The arms that looked best within domain under R2 (`sparse_fisher_lloyd100` 0.170, `blockmodel100` 0.168, `binarize_global_lloyd100` 0.168) are mid-table on r (0.254, 0.244, 0.254). So the earlier reading that the within-domain winner and the transfer winner are different arms was an artifact of comparing R2 with r; on one measure `vmf_ward100` wins outright. The `blockmodel` finding survives unchanged: it optimises the R2-style objective directly, tops it, has the highest hubness of any arm, and transfers near the bottom.

**YOLO 2 answers its question, in the affirmative and against itself.** Directly optimising the block-model objective works: `blockmodel` reaches within-domain fidelity R2 0.195 (Δp 0.148) at k = 50 and 0.217 (Δp 0.168) at k = 100, the best within-domain numbers of any arm, and its reliability (0.690) nearly equals its restart-split ceiling (0.680). But it has the **highest hubness AMI of all 16 arms** (0.340 at k = 50) and among the worst transfer (across-domain fidelity Δp 0.058 / 0.079 against 0.224 for `vmf_ward100`). The pre-registered risk from Iteration 14 -- that block means reward hubness sorting -- is exactly what happened. This is the cleanest available demonstration that fidelity alone cannot select a method: the arm that maximises it is the arm that transfers worst.

**YOLO 4, ICA.** On hard labels ICA is the weakest arm: reliability 0.275, within-domain fidelity 0.038 (Δp 0.030), across-domain fidelity Δp 0.083. On its own object it is not weak at all: `reliability_within_maps` = **0.664** at k = 50 and 0.555 at k = 100, far above its label reliability of 0.275 / 0.234, and it has the **lowest hubness AMI of any arm** (0.021), i.e. the least trivial parcellation in the set. ICA is not a competitive partition method here, and the map metric is what stops that being misread as a failed decomposition. Its k = 100 run is also the only arm whose transfer improves markedly with k (Δp 0.083 -> 0.119).

**YOLO 4, the sparsification rungs, all one change from `fisher_pca_lloyd`.** The hubness prediction holds precisely. `binarize_row_lloyd` (row-wise threshold, which equalises every row's density and so removes hubness by construction) has hubness AMI **0.103** and across-domain fidelity Δp **0.113**; `binarize_global_lloyd` (one threshold for the matrix, so hubs keep more partners) has hubness AMI **0.279** and Δp **0.045**. **The standardized family still owns transfer, and k = 100 helps it.** The four best arms by across-domain fidelity Δp are `vmf_ward100` (0.224), `vmf_ward` (0.201), `vmf_lloyd100` (0.189), `vmf_lloyd` (0.166) -- all with hubness AMI 0.07-0.10, the lowest in the set apart from ICA. `vmf_ward100` is also respectable within domain (Δp 0.151, fourth of 16) and has a restart-split ceiling of 1 by construction. **What was built for T1, T2 and T5.** [configs/final_mlp.yml](../configs/final_mlp.yml) (15 arms: T1's MLP arms, all of T2, T5) and [configs/final_resid.yml](../configs/final_resid.yml) (residual Ward at k = 150 and 200), each its own tree with connectivity hard-linked from `results/yolo_mlp` and `results/yolo` and a `connectivity` section identical to the source config's (under test). Three code additions, one flag each:

- `sparsify_profiles` (`model.sparsify_standardized`): after standardizing, keep each row's top 10%, zero the rest, re-standardize. The kept set is the one thresholding the magnitudes would keep, but the order decides the values: thresholded magnitudes keep their offset from zero, so a unit with a high baseline gets a nearly binary profile and a unit with a low baseline a graded one, and the level leaks back in through the profile's shape. For one exponential pattern at two baselines the old order gives two profiles correlated at 0.972; the new order gives one profile. Re-standardizing puts the rows back on the sphere, so distance is again a function of profile correlation.
- `clustering: ward_kmeans`: Ward, then Lloyd from Ward's centroids. Deterministic (one sample, ceiling 1) and at a k-means local optimum; on an overlapping planted mixture the Lloyd step moves most of Ward's partition (ARI with Ward 0.37) and lowers the inertia from 4,284 to 3,910.
- `blockmodel_center` (`metrics.center_connectivity`): the refinement target with each unit's level removed. `double` is the exact least-squares additive fit over off-diagonal pairs; `degree` subtracts the configuration-model expectation r_i r_j / sum(r) of the modularity matrix (Newman 2006, PNAS 103:8577-8582), the correction the degree-corrected block model builds in (Karrer & Newman 2011, Phys. Rev. E 83:016107). Fidelity is still scored on raw |r|.

**An issue found in T5 while implementing it, and the arm added for it.** The approved design was double-centring. It removes an additive per-unit effect exactly but leaves (theta_i - mean)(theta_j - mean) of a multiplicative one, which a block model fits by grouping strong units together again; the modularity correction removes a multiplicative effect and leaves -(a_i - mean)(a_j - mean) / (2 mean) of an additive one. Which form hubness takes in these connectomes is not known, and a shared factor (r_ij ~ lambda_i lambda_j) is multiplicative. On a planted generator (6 pattern blocks, lognormal per-unit strength, refinement from a 20%-corrupted start), raw refinement drops to ARI 0.01 with hubness AMI 0.66 under a strong multiplicative effect and to 0.31 / 0.37 under an additive one; `degree` keeps ARI 1.000 under both; `double` keeps 1.000 under the additive effect and leaks to 0.975 under the multiplicative one. So T5 runs three arms rather than two: raw (the control), `double` (as approved) and `degree` (added; one arm, about 4 CPU-hours). If the two centred arms differ in hubness AMI, that also says which form hubness takes. Each T5 arm recomputes Ward instead of reading `vmf_ward100`'s files, to avoid a cross-job dependency. k = 100 because T1 has not chosen k yet, and the polish is cheap to rerun at another k.

**Two smaller decisions.** The PCA arms apply PCA after standardizing, without whitening and without re-normalizing the rows, so the discarded components are treated as noise; re-normalizing to the sphere would amplify the noise of units with little shared structure. d = 20 is deliberately below k - 1 = 99, the strong-denoising end of the test. And restricted score jobs over long arm lists are now named `<n>arms_<digest>` (`util.variants_tag`): the 13-arm early score is 215 characters joined, and its SLURM log path would have reached the 255-byte file-name limit. Lists up to 100 characters keep their old names, including every one used so far.

T2: if denoising was the reason, the PCA Lloyd arms' restart ceilings rise above 0.9 and their split-half reliability by 0.1-0.2 at a within-domain r cost under 0.02; if sparsification was, the sparse arms reach the reliability of the row-binarized arms with a standardized-family reference (across-domain pnull r near 0.05, not 0.10). **What was built.**
- `blockmodel_refine_stage: consensus` refines the finished consensus once, and each restart-split consensus the same way, so the ceiling stays like for like. It keeps the unrefined consensus as `parcellation_unpolished`. The per-restart path of Iterations 14 and 17 is unchanged and remains the default.
- `consensus: coassociation` builds the co-association matrix of the restarts as integer counts, one cluster at a time. This is evidence accumulation (Fred & Jain 2005, IEEE TPAMI 27:835-850). It then cuts 1 minus the co-association fraction into exactly k clusters by average linkage. The split consensuses are built the same way from each half of the restarts. Each unit's mean co-association with every cluster is stored as `coassoc_membership`.
- `store_samples` (default on) writes the restart labels as int16, about 800 KB per file.
- The scorer adds `reliability_within_coassoc`: the split-half Pearson correlation of the two halves' co-association matrices over unit pairs. Its partition-null reference averages both orientations, as the ARI reference does. It judges the restart ensemble, so an arm whose restarts spread over many comparable optima is penalised only for spreading them differently on the two halves.
- `triviality` gains `entropy_effective_networks`, exp of the entropy of the network sizes. It sees what the non-empty count cannot: one giant network plus singletons.
- `metrics.crossfit_yardstick` computes the centroids of one half's consensus on that half's standardized profiles, runs Lloyd on the other half from them, and takes the ARI between the start and the landing point. It also reports the ordinary split-half ARI, and the inertia of the landing partition over that of the half's own consensus. The driver rebuilds the profiles exactly as `sample_parcellations` does for a standardized Fisher arm, in float32 and without the arm's PCA, and refuses any other arm. Its `pnull` rows start from the null tree's partitions, with centroids on the real profiles.
- `score.domains` and `score.across_pairs` are config options, validated.

**Choices made while building, and why.**
- **The polish acts on the consensus, not on every restart.** Per-restart polishing would cost 40 refinements per matrix, and the object reported is the consensus.
- **The cut uses `cut_tree`, not `fcluster(maxclust)`.** A co-association distance takes only n_samples + 1 values, and `fcluster` returns fewer clusters wherever distances tie. `cut_tree` is exact for monotone linkages such as average.
- **Singletons are a known risk of average linkage, recorded rather than engineered away.** Units that are unstable across restarts co-occur with no one, merge last, and can become singleton clusters at the cut. The new entropy count is how that would show. A reassignment step would make the arm a different method.
- **The yardstick runs on full profiles.** It is a property of the data at this k, and full-profile Lloyd is what the PCA-100 arms approximate.
- **Pools weight members equally.** A pool of m domains carries m times one domain's tokens. That is part of what pooling buys, and any comparison of a pool with a single domain carries it.

**Found while testing: the Hungarian consensus is reproducible only up to the naming of networks.** `align_samples` seeds the greedy alignment with the lowest-inertia restart. Identical Lloyd runs return identical labels, but their inertias can differ by about 2e-12 between runs, so where restarts tie the sort order changes. With identical partitions only the column order changes, so every ARI-based metric is unaffected. With distinct restarts tied to within numerical noise, the soft consensus could also differ slightly. This predates this round. It is left unchanged, because rounding the scores before sorting would change the partitions of every earlier arm that had a tie. Tests compare consensuses up to label permutation.

**How the results will be read, stated before they exist.**
- **Polish:** a polish is kept if across-domain fidelity Δp does not fall and within-domain fidelity rises, relative to the unpolished consensus with the same restarts. Among the kept polishes the choice is by across-domain fidelity Δp, ties within 0.01 going to lower hubness AMI, provided within-domain reliability drops by less than 0.05.
- **Co-association consensus:** better if the restart-split ceiling and the split-half reliability both rise against the Hungarian consensus of the same restarts, with fidelity r within 0.01 and `entropy_effective_networks` above half of k.
- **200 restarts:** if the ceiling rises toward 1 while split-half reliability does not, hard-label reliability at k = 100 is limited by the data rather than the restarts.
- **Yardstick:** below 0.6, the data do not pin down 100 hard networks, and the reliability to report is `reliability_within_coassoc` or a lower k. Well above the observed 0.62, the consensus rather than the data is the bottleneck.
- **k:** the smallest k after which across-domain fidelity Δp gains less than 0.01 per doubling.
- **Pooled estimation:** it helps if leave-one-out transfer into a domain beats the mean single-domain transfer into it by at least 0.02 in fidelity r Δp. It must also raise across-domain label agreement over the single-domain pairs. The complementary-split agreement is the domain-general reliability to report.

## Iteration 22 -- stage 1 begins: Pythia training dynamics on all MLP neurons (2026-09-21)

Method selection is over (Iteration 21). The confirmed pipeline is now applied to models it was not selected on. First experiment: whether the networks emerge over training, on Pythia checkpoints. Planned with Andrea before any code; every decision below was agreed on 2026-09-21.

**Design.**
- **Models:** pythia-70m (6 layers x 2048 neurons = 12,288 units) and pythia-160m (12 x 3072 = 36,864), the standard (non-deduped) suite. 410m would be 98,304 units and a 39 GB matrix, beyond the in-memory PCA, sparsification and scorer; deferred until there is out-of-core code.
- **All MLP neurons are units.** Every GPT-2 selection arm clustered a seeded 832-of-3072 subsample per layer so that n_units matched the residual stream; that was a comparability device, and Andrea's rule is that the actual experiments use every neuron (`units_per_layer: null`). For GPT-2 that will be 36,864 units too.
- **Checkpoints:** step 0 (the initialisation, the true baseline for "emergence") plus 1, 4, 16, 64, 256, 1000, 4000, 16000, 64000, 143000, a factor of about 4 apart; all are checkpoints Pythia saves.
- **Data:** unchanged from the GPT-2 runs: the four prose domains, 4 samples of 98,304 tokens, `seq_len` 1024, seed 42, so every checkpoint sees the same documents and only the weights vary. At 36,864 units the units-per-token ratio on a half is 0.19 against 0.05 in the selection runs; the connectome is noisier per entry, and the uncompressed ceiling is reported next to every number so that is visible. The alternative, 4x the tokens, no longer fits one a6000 and was declined.
- **Pipeline:** exactly the Iteration 21 arm (Fisher-transformed standardized profiles sparsified to their top 10%, PCA-100 unwhitened, Lloyd with 200 restarts and Hungarian consensus, k = 100), one variant named `final`, fitted within one domain.
- **Metrics:** the usual four against the null partition, plus two cross-checkpoint ones: ARI between the real partitions at consecutive checkpoints and against the last checkpoint, each with a `pnull` reference built as the within-domain one is (mean of null-at-s against real-at-s' and the reverse). Fidelity of the final partition on earlier connectomes was considered and dropped, because the connectomes are purged.
- **Storage:** juice6 had 37 TB free on 2026-09-21, but the default layout at 36,864 units would write 7 files of 5.4 GB per domain and tree, about 300 GB per checkpoint, and hold 4 sample matrices plus their sums in RAM. So the connectivity step writes the two split halves directly (`outputs: [halves]`), the parcellation consumes only the halves (`parcellate_keys`), and a `purge_connectivity` step deletes both trees' connectivity once `metrics/scores.csv` exists, leaving a manifest. About 86 GB transient per 160m checkpoint.

**How the results will be read, stated before they exist.** Networks emerge if within-domain reliability and fidelity above the null rise monotonically with log step, and the ARI to the final partition rises toward the final checkpoint's within-domain reliability. Step 0 is not expected to score zero: random weights already induce correlated units, and whatever structure it has is the baseline the trajectory is read against. The method generalises if the final checkpoints reach numbers of GPT-2's order (within ARI about 0.7, across-domain fidelity above null about 0.1). Across-domain ARI is expected to stay near 0.1; a rise with training would be the interesting result.

**What was built.**
- `get_model_and_tokenizer(revision=...)` loads a Hub checkpoint and casts the model to float32, so the connectome does not depend on a checkpoint's stored dtype; `run_connectivity(revision=...)` records it, with `model_name`, `unit_type` and `n_units`, in every half file's provenance.
- `MLP_PROJECTIONS` / `mlp_projections`: the MLP hook is resolved by architecture (GPT-2 `h[i].mlp.c_proj`, GPT-NeoX `layers[i].mlp.dense_4h_to_h`), a forward pre-hook on the output projection whose input is the post-GELU state; unknown architectures fail loudly. Verified on a tiny GPT-NeoX against a hook on `mlp.act`. Pythia's parallel attention and MLP do not change the unit definition.
- `run_connectivity(outputs=...)`: `samples`, `avg`, `halves` in any combination; `halves` keeps running Fisher sums per half and tree, writes a half as soon as its last sample is in, and frees it. Verified equal to `run_split_halves` over the per-sample files in both trees, and `[halves, avg]` equal to the legacy average. Skips a domain whose halves exist before the dataset is loaded.
- Streaming fidelity: `block_means`, `fidelity`, `fidelity_insample` and `fidelity_ceiling` now accumulate over row blocks (`pair_agreement`) instead of copying the matrix to float64 and forming an n x n prediction, which at 36,864 units was four to five copies of 11 GB. Equal to the direct computation to 1e-10 (r2 and r); every earlier suite passes unchanged.
- The scorer skips the `avg` across-domain pass, without recording anything as missing, when a tree has no avg files.
- `-s purge_connectivity` in `main.py`: never part of `all`; needs `purge_connectivity: true` in the config and an existing `metrics/scores.csv`; writes `connectivity_purged.txt` with the deleted files and sizes.
- `parcelmate/bin/score_checkpoints.py`: the two cross-checkpoint metrics with their `pnull` reference, plus `scores_all.csv`, one long table over checkpoints with `model` and `step` columns. Refuses partial tables.
- `scripts/make_pythia_configs.py` writes the 22 configs in `configs/pythia/` (committed, so a run reproduces from the repository); `scripts/launch_pythia.sh generate | submit <size>` renders and chains, per checkpoint, a GPU connectivity job, a CPU parcellation job and a CPU score-and-purge job, then one cross-checkpoint job per size after all its chains.
- [tests/verify_iter12_pythia.py](../tests/verify_iter12_pythia.py): the hook, the loader, the halves mode against the legacy layout, the streaming metrics, the scorer on a halves-only tree, the purge step and its refusals, the cross-checkpoint scorer on two fake steps, every generated config bound to the pipeline signatures and equal to the confirmed arm, and the launcher's step list.

**Sizing, from the anchors.** GPT-2 MLP connectivity at 9,984 units took 19 min on an a6000 at 15.8 GB. At 36,864 units the timecourse array is 14.5 GB and its shifted copy another 14.5, one 5.4 GB matrix per tree and one half's sums per tree: about 45 GB peak, requested at 64 GB and 3 h; the correlation itself fits the GPU in one tile (two 14.5 GB operands plus the result). Parcellation holds a few copies of the matrix through sparsification and PCA: 48 GB, 5 h (PCA-100 Lloyd at 200 restarts took 57 min for 24 matrices of 9,984 units; here 16 matrices of 36,864). Score 64 GB, 6 h. 70m is a tenth of all of it. Total about 25 GPU-hours and 100 CPU-hours across 22 chains.

**Found while testing.** Restructuring the sample loop had left the null-tree sample write outside its `if null_model` guard, so the legacy layout without a null tree would have failed; caught by a check added for it. And the suite's temporary trees exhausted the local /tmp quota; it now works under `tests/.tmp`.

- 2026-09-21 (final pipeline confirmed): **the confirmation arm passed both conditions of its rule (within ARI 0.707 ≥ 0.68; fidelities within 0.001 of the base or above), so the final pipeline stands as decided on 2026-09-15.** No further selection runs on GPT-2; every remaining question (k, the small sparse-profile margins, across-domain agreement) goes to the second model. The dimensions varied across all 55 arms and what each bought are recorded in [METHOD_SELECTION.md](METHOD_SELECTION.md). Iteration 21.
- 2026-09-15 (confirmation rule): **the combination of sparse profiles and 200 restarts is final if its within-domain ARI is at least 0.68 and no fidelity falls more than 0.005 below the base arm; otherwise the final pipeline is 200 restarts without sparse profiles.** The 0.005 tolerance was added before the run, because a strict "no fidelity below the base" would also fail 200 restarts alone on noise-sized differences. Iteration 21.
- 2026-09-15 (Andrea, design constraint): **all clustering is obtained within a single domain.** No connectome is pooled across domains, for any partition, at any stage. Domain generality is assessed only by fitting on one domain and evaluating on another. This removes pooled estimation from the final pipeline decided the same day; the pooled-estimation results (T4, Iteration 20) and `plots/pooled_estimation` stay as a record only. The `pool_domains` step and `configs/pooled_mlp.yml` remain in the code but are not part of the final design.
- 2026-09-15 (final pipeline): **MLP neurons, standardized Fisher profiles sparsified to the top 10% per unit, PCA-100 unwhitened, Lloyd k-means with 200 restarts and Hungarian consensus, k = 100, fitted within a single domain.** *(As first written: "estimated on the connectome pooled over domains"; corrected by the design constraint above.)* Each rule stated in Iteration 19 was applied as written.
  - **Block-model polish:** dropped. It raised fidelity in every domain but cut within-domain reliability by 0.13-0.22, past the 0.05 limit, and lowered across-domain agreement in all 12 pairs.
  - **Co-association consensus:** dropped. Neither the ceiling nor the reliability rose.
  - **200 restarts:** kept. Ceiling +0.118 and reliability +0.064, both 4/4, with fidelity unchanged; the yardstick at 0.78 confirmed the consensus was the bottleneck.
  - **Sparse profiles:** kept. Consistent small gains at no cost.
  - **Pooling:** passed its rule (leave-one-out gain +0.021, positive in 4/4 domains) but is excluded by the single-domain constraint.
  - **k:** not settled by its rule (fidelity still gains over 0.01 per doubling at 200), so k = 100 was kept as a judgement that balances fidelity against 0.065 of reliability lost per doubling. To be revisited on the second model.

  The exact combination was confirmed on 2026-09-21 (Iteration 21). Iteration 20.
- 2026-09-14 (last round): **the remaining tests run as one round: the candidate pipeline (PCA-100 Lloyd consensus with a consensus-level block-model polish), T3 and T4; the second-model replication follows it.** The polish refines the consensus once rather than every restart (40x cheaper, and the consensus is the reported object). The co-association consensus is cut by average linkage with `cut_tree`, whose cut is exact, not `fcluster`, which ties would under-fill. The Hungarian consensus's dependence on last-bit inertia ties (label naming only, pre-existing) is documented, not changed, so earlier arms stay reproducible. t-SNE and UMAP were advised against for the features, because PCA already solves speed and they break the link between the clustering objective and the scored fidelity. Iteration 19.
- 2026-09-14 (unit and algorithm): **MLP neurons are the unit, and Lloyd consensus is preferred over Ward.** On the residual stream Ward's reliability and transfer rise with k together with its AMI with the dimension index; on MLP units, which have no chains, Ward's transfer lead over Lloyd vanishes (across-domain fidelity Δp 0.100 against 0.101 at k = 100) and its reliability is far lower (0.24 against 0.61). The Iteration 17 recommendation of Ward is withdrawn. The block-model polish is kept as the fidelity lever; which centring to use is open, because on MLP units the hubness it adds also transfers. Iteration 18.
- 2026-09-13 (final tests): **T1, T2 and T5 run first; T3 and T4 wait; a second model replicates the choice before it is called final.** Andrea approved the three tests that need at most a flag each (Iteration 17). T5 runs one arm beyond the approved design, the `degree` (modularity) centring next to the approved `double` centring, because double-centring leaves a rank-1 residue of a multiplicative per-unit effect that a block model fits by grouping strong units again (shown on a planted generator); flagged to Andrea with the launch. Rejected for now: re-normalizing rows after PCA (amplifies the noise of units with little shared structure), sparsifying magnitudes before standardizing (lets a unit's baseline back into the shape of its profile), and reading Ward labels from `vmf_ward100`'s files in the T5 arms (a cross-job dependency to save about 3 CPU-hours per arm).
- 2026-09-13 (selection criterion): **across-domain fidelity against the partition null is the criterion; within-domain reliability is not.** Hubness AMI correlates +0.82 with within-domain reliability Δp and **-0.70** with across-domain fidelity Δp, so what buys reliability costs transfer, and the arm that maximises the within-domain R2 objective directly (`blockmodel`) transfers near the bottom. Iteration 16.
- 2026-09-13 (measure): **compare fidelities like for like, in Pearson r.** R2 is undefined across domains, so a within-R2 against across-r comparison mixes measures; doing so made the two look orthogonal (-0.04) when on r they correlate +0.59. R2 rewards predicting the connectivity's overall level, which is exactly what a hubness partition supplies, so R2 and r disagree systematically about which arm is best. Report both within-domain, and compare only r with r. Iteration 16 correction.
- 2026-09-11 (YOLO runs): **after the one-change ladder, run bundled multi-change arms chosen for expected value per hour**, since the ladder is stage 0 and the chosen method will be validated across models. Three built the same day (Iteration 14): converged optimizer + Ward, direct block-model optimisation, MLP neurons as units. Every k gets its own matched null partition. |z| stays retired.
- 2026-09-11 (null design): **the primary reference is the null partition evaluated on the real data (`pnull`), not the pipeline evaluated on null data (`null`).** Andrea's correction. The latter compares R^2 on two different matrices and is what let a structureless matrix out-score real data; the former puts both partitions on the same target and measures the clustering's credit beyond per-unit properties. `null` is kept as a column for the record. |r| returns as the primary connectome; |z| becomes one rung (`vmf_z`). Iteration 12.
- 2026-09-08 (S1): knockout is **opt-in and per-network**. `run_knockout(networks=None)` is a no-op, so `-s all` never lesions a model by accident; `networks: all` or a list of indices builds one perturbed model per shared subnetwork, each writing to `<output_dir>/knockout/subnetwork<k>/`. The union-lesion the old OR-loop performed is no longer reachable — it could not answer what any single subnetwork contributes, which is the question the step exists to ask. Re-addable if a "remove all domain-general structure" experiment is ever wanted. Cost: one full connectivity run per selected network, so `networks: all` over 20 shared networks is 20x the baseline connectivity cost. Rejected alternative: per-network as the default (my initial recommendation) — Andrea preferred an explicit opt-in so no accidental lesioning is possible.
- 2026-09-08 (S1, ablation value): **mean-ablation by default**, `ablation: zero` retained as an option. Zero is off-distribution and conflates "network removed" with "input broken". The mean is taken **per domain**, read from the baseline run's cached `unit_means` for whichever domain is being processed, because a unit's mean activation differs substantially across domains (Iteration 1 diagnostics) and one global set of values would be off-distribution for most of them. Implemented by caching `unit_means`/`unit_stds` during the baseline connectivity run and adding `PerturbedModel.set_perturbation_values` to swap values between domains. Rejected alternatives: a single global mean (simpler, weaker rationale); computing means on the fly at knockout time (no baseline change, but roughly doubles forward passes on a step already N-times the baseline cost).
- 2026-09-08 (S1, controls): **deliberately deferred.** No size-matched or variance-matched random-lesion controls yet, so a deficit observed after a lesion is not yet interpretable on its own. `unit_stds` is cached now specifically so variance-matched controls can be built later without re-running the baseline. Note that the integration run already shows why this matters: network 0 covered 847 units and network 2 covered 2819, so comparing them directly is confounded by lesion size.
- 2026-09-08 (S3): knockout reads its own **`subnetwork_knockout`** config section, and `model_name` is **inherited from `connectivity`** and rejected if set under `subnetwork_knockout` — a lesioned run must use the same model as the baseline it is compared against. `seed` and `overwrite` are now forwarded. `run_knockout` also filters the connectivity section it passes through, so keys it controls itself cannot collide.
- 2026-09-07 (M8): chose **explicit invalidation plus merge-on-append**, rather than preserving the parcellation across a connectivity rewrite. Preserving it was the obvious reading of "fix the data loss" and is wrong: the parcellation is a function of the connectivity, so keeping it after a recompute yields a stale parcellation silently attached to a different matrix — a correctness bug that no log line would reveal, and worse than the loss it avoids. So the truncation stands, and `warn_dropped_keys` now names the discarded key, the file, and the remedy. Separately, `save_h5_data` gained `merge=True`, used by `run_parcellation` to write only the parcellation: appending a ~2 MB array previously rewrote the ~400 MB connectivity matrix and left a window in which a crash mid-write destroyed the connectivity as well. Also replaced a `load_h5_data` in `run_connectivity`'s cache check with the new metadata-only `h5_keys`, which had been reading the entire matrix to test for two keys. Rejected alternative: separating derived products into their own files (the cleanest design, since co-locating a derived product with its input under a truncating writer is the root cause, but it touches `run_parcellation`, `run_subnetwork_extraction` and all three plot functions — deferred).
- 2026-09-07 (S7, seeding scheme): chose **hierarchically derived sub-seeds** over a single global seed. A master `seed` in the config supplies the default for every step; each step derives sub-seeds from it via `util.derive_seed(seed, *keys)`, keyed by domain, by sample index, and by parcellated filename. Rationale: the pipeline caches to HDF5 and skips completed work, so re-running one domain or one file is a normal operation, and it must reproduce exactly what the full run produced for that unit. A single RNG stream would make each domain depend on how many draws preceded it. `derive_seed` uses hashlib rather than the builtin `hash()`, which is salted per process for strings. Within `sample_parcellations` a single `RandomState` is shared across the reductions and all clustering restarts, deliberately: reusing one fixed `random_state` for every restart would make all 100 restarts identical and destroy the consensus averaging, whereas drawing from one stream keeps them different *and* reproducible as a set. Verified: 12 of 12 restarts distinct within a run, and identical across runs. Rejected alternative: seeding only globally at process entry (simpler, but breaks single-domain re-runs).
- 2026-09-07 (M4): chose **option 3, restrict parcellation to `avg` files**, exposed as `parcellate_samples=False`. Cuts the longest stage to a fifth at `n_samples: 4`. Reversible without recomputing any model forward pass, because the per-sample connectivity HDF5s are cached; set `parcellate_samples: true` to recover them if parcellation stability becomes a claim.
- 2026-09-07 (M6): chose the **full reciprocal-best-match clique**. A network survives only if, for *every* pair of domains, the two networks assigned to it are each other's best match. The previous implementation chained matches along the alphabetically sorted domain list, verifying only `n_domains - 1` of the `n_domains * (n_domains - 1) / 2` pairs; that made the surviving set depend on domain *names* (sort position decided which domains were interior, load-bearing links) and let identity drift across hops, since the two ends of the chain were never compared. Also added an explicit `domains` argument to `run_subnetwork_extraction`, which is the mechanism for excluding the `random`/`whitespace` baselines from the definition of domain-generality; the Iteration 1 diagnostics give empirical support for excluding `whitespace` in particular. Rejected alternatives: a star topology against a designated reference domain (order-independent but privileges an arbitrary reference), and replacing the binary filter with a continuous cross-domain consistency score (more informative, and still the better long-run design, but deferred because the shared network is not a central claim of the current analysis).
- 2026-09-07 (S4 footing caveat, revisited): left as is. The final layer's connectivity is still computed on post-`ln_f` values while layers 0-11 are raw residual-stream values. Recorded here so it is not rediscovered as a bug; revisit if layer-12 behaves anomalously in the parcellation.
- 2026-09-03 (S4 fix): chose to map the final hidden-state index onto a wrapped `ln_f` (so the lesioned quantity is exactly the measured quantity) rather than dropping the final hidden state from the analysis. Rationale: preserves all 13 layers and all downstream shapes; the post-LN state is what downstream computation actually consumes. The alternative (excluding `hidden_states[-1]`, or re-deriving it pre-LN) remains on the table if the post-LN footing of layer 12's connectivity becomes a concern.
- 2026-09-03 (S5 fix): chose min-max-normalized inverse-inertia weights (`w = 1 - minmax(inertia)`, best sample → 1, worst → 0, all-equal degenerates to unweighted). Note: the worst sample now gets weight 0, i.e., is excluded when weighting is on. Alternatives (rank weights, softmax over −z(inertia)) not pursued for now.
- 2026-09-04 (dataset substitutions): `datasets` 4.x removed loading-script support, which killed two of the five text domains outright. Replacements chosen empirically rather than by reputation:
  - **bookcorpus** -> `rojagtap/bookcorpus`. Verified to be a faithful parquet mirror: its first streamed row is byte-identical to the original `bookcorpus` ("the half-ling book one in the fall of igneeria series ..."), same sentence-level `text` field. `SamuelYang/bookcorpus` returns the same row and is an equally good fallback.
  - **tldr17** -> `dim/tldr_17_50k`. Preserves the original webis schema (`body`/`content`/`summary`), so `get_dataset`'s content-key autodetection still selects `content` (the post body) as before. **Caveat for the paper: this is a 50,000-post subset of the ~4M-post `webis/tldr-17`, not the whole corpus.** At the default budget (400k tokens/domain) the subset is far more than sufficient, but the tldr17 domain is now sampled from a smaller pool than the other domains, and `shuffle` operates over the whole 50k rather than over a sample of millions. Revisit if a properly mirrored full tldr-17 appears on the Hub.
  - **wikitext** -> `Salesforce/wikitext` (same data, namespaced id; bare repo ids are no longer valid).
  Alternatives considered and rejected: `lucadiliello/bookcorpusopen` (BookCorpusOpen is a *different, larger* corpus with document-level rather than sentence-level segmentation — not a drop-in); pinning `datasets<4` (would freeze the project on an unmaintained release to preserve two dataset loaders).
- 2026-09-04 (cluster job generation): chose **versioned YAML cluster profiles** (`configs/cluster/*.yml`) over a `--preamble` file of raw shell lines for supplying cluster-specific settings to `make_jobs.py`. Rationale: the profile is committed alongside the code, so a run is reproducible from the repository alone and the SC setup is self-documenting; a preamble file would have been more flexible but would have pushed the cluster knowledge into an untracked file. Precedence is CLI flag > profile > built-in default, so profiles act as baselines and one-off deviations stay on the command line.
- 2026-09-04 (partition assignment): chose to **split the pipeline across partitions by step** rather than run everything in one GPU allocation. `connectivity` and `subnetwork_knockout` are GPU-bound and go to `jag-standard` (a6000); `parcellation`, `subnetwork_extraction` and the `plot_*` steps are sklearn/CPU workloads and go to `john` (CPU-only). Rationale: the clustering stage (MiniBatchKMeans x100 plus Hungarian alignment) is likely the longest wall-clock stage and would otherwise hold a contended GPU idle throughout. Costless because `/juice6` is mounted cluster-wide and the pipeline already caches to HDF5 between steps.

- 2026-09-08 -- [info/PARCELLATION_DESIGN.md](PARCELLATION_DESIGN.md) -- **decision 2.1 settled: keep `|r|`.** Rationale (Andrea): in fMRI a deactivation is a physical event with a direction, so sign is interpretable and task-negative structure is a finding; a residual-stream dimension has no comparable privileged direction, so its sign is closer to a coordinate convention and an anticorrelation between two units does not carry that interpretive weight. Taking `|r|` makes the analysis invariant to the convention. Limitation recorded rather than fixed: the method cannot distinguish co-activation from reciprocal trade-off, and the signed matrix is preserved on disk if a later claim needs it. Stage 1 of the recommendation, Stage 3's SBM weight description, and the open-decisions list were all amended for consistency. Also rewrote 2.3 (PCA truncation and whitening) in plain terms: PCA compresses the *columns* of the unit-by-connection table, not the rows, so units are never transformed and the parcellation is not in a rotated unit space -- what changes is the description used to judge similarity between units, with truncation (54.7% of variance dropped) and whitening (0.074%-variance direction weighted equally with the 2.8% one) as the two consequences.

## Cluster

Compute for this project runs on the Stanford SC cluster (NLP group, CLiMB lab). Connection, storage layout, SLURM conventions, cluster profiles and job-launching instructions are in [CLUSTER.md](CLUSTER.md).

Code moves to the cluster by git (so every result traces to a commit hash) and results come back by rsync through the `scdt` data-transfer node. A full run is two submissions: `connectivity` on a GPU partition, then the clustering and plotting steps on a CPU partition.
