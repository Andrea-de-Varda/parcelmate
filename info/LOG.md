# parcelmate — project log

This is the running record of everything done to this codebase: project structure, all issues found, every design decision, and a dated log of every edit. It exists so that the eventual paper's methods section can be reconstructed exactly. Update it whenever anything changes. (Kept separate from README.md, which belongs to the upstream repo; merge relevant parts there later if desired.)

## What the project does

parcelmate applies the methodology of fMRI functional connectivity analysis to the internals of a language model. Each hidden unit of an LLM (a single dimension of the residual stream at a given layer boundary) is treated as a voxel; its "timecourse" is its activation across tokens of naturalistic text. The pipeline: (1) **connectivity** — run a HuggingFace model (default GPT-2) over text from several domains (wikitext, bookcorpus, agnews, tldr17, codeparrot, plus `random` and `whitespace` baselines), extract per-unit timecourses, and compute the unit-by-unit Pearson correlation matrix, averaged (Fisher-z) over 4 independent ~100k-token samples; (2) **parcellation** — binarize the absolute connectivity at each unit's 90th percentile, PCA to 200 components, run MiniBatchKMeans (k=50) 100 times, align the runs with the Hungarian algorithm, and average into a soft parcellation (unit × network membership probabilities); (3) **subnetwork extraction** — keep networks that are reciprocal best matches across all domains (chained in alphabetical domain order) and average them into a "shared" (domain-general) parcellation; (4) **knockout** — clamp the units belonging to shared subnetworks to zero via `PerturbedModel`/`PerturbedLayer` wrappers and re-run the connectivity pipeline on the lesioned model; (5) **plots** — connectivity clustermaps, network heatmaps, and stability analyses (correlations of connectivity matrices across samples and domains). Everything is cached as HDF5 under `results/`, driven by `python -m parcelmate.bin.main <config.yml> -s <steps>`; `parcelmate/bin/make_jobs.py` generates SLURM scripts.

Method design decisions -- which pipeline steps are free choices rather than necessities, what the alternatives are, and why -- are recorded separately in [PARCELLATION_DESIGN.md](PARCELLATION_DESIGN.md). This file records bugs, fixes and the dated edit history.

Code map: [parcelmate/model.py](../parcelmate/model.py) (pipeline + perturbation machinery), [parcelmate/data.py](../parcelmate/data.py) (datasets, tokenization, filtering, correlation), [parcelmate/plot.py](../parcelmate/plot.py), [parcelmate/util.py](../parcelmate/util.py) (HDF5 I/O), [parcelmate/cfg.py](../parcelmate/cfg.py) (YAML config), [parcelmate/constants.py](../parcelmate/constants.py), [parcelmate/bin/main.py](../parcelmate/bin/main.py) (CLI driver).

- M11. **New, found 2026-09-08 while verifying mean-ablation.** An ablated unit is constant by construction, so its variance is zero and its correlations are undefined. In practice `correlate` yields an all-NaN row for the units whose residual std underflows to exactly zero (233 of 847 in the integration run) and all-zero correlations for the rest (614) — semantically correct in both cases, but inconsistent, and `run_parcellation`/`plot_stability` then apply `np.nan_to_num`, so the distinction disappears silently. The consequence is methodological: a whole-matrix baseline-vs-knockout comparison conflates the *mechanical* effect of the lesioned rows becoming degenerate with the *scientific* effect of reorganization among the surviving units. Measured in the integration run: r = 0.470 over the whole matrix versus r = 0.659 restricted to intact units. Pre-existing (zero-ablation has the same property) but only observable now that knockout runs. **Recommendation: restrict the knockout stability analysis to intact units, and mark all lesioned units NaN explicitly so downstream code excludes them deliberately rather than by accident.** OPEN — decision needed before knockout results are interpreted.

## Iteration 1 — basis and thread diagnostics (2026-09-07)

Run on the seven-domain `results/alldomains` connectivity matrices (GPT-2, local verification run) before committing to any downstream analysis. Motivation: the residual stream accumulates, `x_{l+1} = x_l + \Delta_l`, so unit *(l, j)* and unit *(l+1, j)* share content by construction. If cross-layer connectivity were dominated by this persistence, the parcellation would be recovering "residual threads" (one dimension tracked through depth) rather than functional networks. There is no brain analogue; it is purely architectural.

**Per-edge, the confound is large.** Mean |r| between the same dimension at adjacent layers, versus different dimensions at adjacent layers:

| domain | same *j* | different *j* | ratio | percentile rank of same-*j* |
|---|---|---|---|---|
| wikitext | 0.867 | 0.051 | 17.0 | 0.996 |
| agnews | 0.866 | 0.048 | 18.2 | 0.997 |
| tldr17 | 0.868 | 0.050 | 17.4 | 0.996 |
| bookcorpus | 0.863 | 0.069 | 12.6 | 0.993 |
| random | 0.894 | 0.053 | 16.9 | 0.998 |
| codeparrot | 0.849 | 0.168 | 5.0 | 0.974 |
| whitespace | 0.737 | 0.406 | 1.8 | 0.859 |

For a given unit, its correlation with its own dimension one layer up exceeds ~99.6% of its correlations with every other dimension one layer up.

**But it does not dominate the clustering signal, because threads are numerically tiny.** The parcellation clusters on a top-10% binarized fingerprint, which selects ~999 partners out of 9,983, while a unit has only 12 same-dimension thread-mates. Measured on wikitext:

| quantity | value |
|---|---|
| thread-mates captured in the top 10% | 11.17 of 12 (93.1%) |
| units capturing all 12 thread-mates | 54.4% |
| threads as a share of selected partners | 1.1% (11 of 999) |
| share of total \|r\| mass on same-dimension pairs | 1.50% (chance 0.12%, so 12x enriched) |

So the thread is almost always fully inside the fingerprint, and it is enriched an order of magnitude over chance, but 99% of the clustering signal comes from different-dimension partners. **Conclusion: the confound is real and must be reported, but it is not a reason to abandon the residual-stream unit definition or to switch to block writes (\Delta) now.** The planned rotation null (see Iteration 2) remains the decisive test, and its two-null variant (shared vs. per-layer rotation) will quantify the thread contribution directly.

**Side findings from the same diagnostic.** Off-diagonal correlation distributions differ qualitatively across domains:

| domain | kurtosis | mean \|r\| | p99 \|r\| |
|---|---|---|---|
| agnews | 25.9 | 0.044 | 0.156 |
| random | 22.5 | 0.050 | 0.177 |
| tldr17 | 22.2 | 0.046 | 0.167 |
| wikitext | 20.2 | 0.047 | 0.170 |
| bookcorpus | 6.5 | 0.065 | 0.235 |
| codeparrot | 0.3 | 0.160 | 0.549 |
| whitespace | -0.8 | 0.373 | 0.915 |

Three things follow. First, `whitespace` is **degenerate**, not merely different: mean |r| is 0.37 and the distribution is platykurtic, meaning nearly everything correlates with nearly everything. This is independent empirical support for excluding it from the domain-general criterion (M6). Second, `codeparrot` is a genuine intermediate case and should not be assumed comparable to the prose domains. Third, `random` is statistically indistinguishable from the prose domains (kurtosis 22.5, mean 0.050), which is direct empirical confirmation of **S6**: the decode/re-encode round trip leaves the "random" baseline far more language-like than uniform random token ids would be.

## Iteration 4 -- reliability and fidelity metrics (2026-09-09)

**Process failure worth recording.** Iterations 3 and the storage refactor built the machinery for the reliability/fidelity experiment -- the circular-shift null, three named variants, provenance -- but never implemented **either metric**. No ARI, no R2, nothing in `parcelmate/bin/` but `main.py` and `make_jobs.py`. Worse, `PARCELLATION_DESIGN.md` contained the word "fidelity" zero times: the metric design agreed in discussion existed only in chat, which is exactly the failure this log exists to prevent. Both halves are now fixed -- the metrics are implemented and tested, and the evaluation protocol is written up as PARCELLATION_DESIGN.md section 6.

- 2026-09-09 -- [parcelmate/metrics.py](../parcelmate/metrics.py) (new), [parcelmate/bin/score.py](../parcelmate/bin/score.py) (new) -- **both metrics implemented.** `reliability` is the adjusted Rand index between argmax labels of two parcellations fit on disjoint halves. `fidelity` fits a partition on half A, estimates each block's mean connectivity **on half A**, predicts half B, and scores R2 over the strict upper triangle -- so both the partition and the values are out of sample. `fidelity_ceiling` predicts half B from half A directly with no parcellation. `triviality` reports AMI against layer index and hubness decile. `score.py` walks the real and null trees, writes a tidy CSV, and prints a null-calibrated summary with domains weighted equally.
- 2026-09-09 -- **Bug caught by the tests, not by inspection.** The first `block_means` used `onehot.T @ onehot` for the pair counts, which is `diag(n)` rather than `outer(n, n)` -- so every off-diagonal block got count zero and the predictions were nonsense (R2 around -150 for a degenerate partition, -2141 for a good one). Fixed to `outer(sizes, sizes) - diag(sizes)`, which also excludes the `R[i, i]` self-pairs so the block means match the strict-upper-triangle scoring. Without the known-answer checks this would have produced plausible-looking rank orderings over arms and been very hard to spot.
- 2026-09-09 -- **The uncompressed reference is not a strict upper bound**, and the exception is informative. It carries all of the fitting half's noise into the prediction, whereas a block model averages that noise away, so a parcellation can beat it when the structure genuinely is block-like and the estimates noisy. Demonstrated both directions on synthetic data (a perfect 5-block partition scores 0.991 against a reference of 0.983; a partition too coarse for 25-block data falls below it). On real connectivity the reference should sit above every variant; a variant exceeding it would be a finding, not a bug. Documented in the docstring and in section 6.
- 2026-09-09 -- [parcelmate/model.py](../parcelmate/model.py), [parcelmate/constants.py](../parcelmate/constants.py), [parcelmate/bin/main.py](../parcelmate/bin/main.py) -- **split halves are now first-class cached artefacts**, not in-memory temporaries. `run_split_halves` Fisher-averages samples 1..n/2 and n/2+1..n into `connectivity_<domain>_halfA.h5` / `halfB.h5`, recording which samples each came from; `INPUT_NAME_RE` and `HALF_NAMES` were extended to match; `run_parcellation` parcellates `avg` plus both halves by default via `parcellate_keys`. So the ordinary parcellation step consumes them, they are cached, and every parcellation of a half carries the usual provenance. `main.py` gained a `split_halves` step and now runs **both** the real and null trees through split-halves and parcellation, since the null is only useful if the identical pipeline runs on it.
- 2026-09-09 -- [tests/verify_iter4_metrics.py](../tests/verify_iter4_metrics.py) (new) -- 24 checks, written to confirm the metrics fail in the *right directions* rather than merely run. The load-bearing one: a data-independent partition (labels fixed by position) scores ARI = 1.000 and R2 = 0.0004, which is the whole argument for why reliability cannot be used alone. Also verifies both metrics collapse on a circshift null, that block means come from the fitting half (a peeking implementation would score better and is detectable), and that a layer-driven partition is caught by the triviality check. 152 checks now pass across five suites, plus 13 pytest cases.
- 2026-09-09 -- [tests/verify_iter4_metrics.py](../tests/verify_iter4_metrics.py) -- added a **full-pipeline integration test**: builds a small real tree and a circshift null tree with per-sample connectivity for two domains, runs `run_split_halves` and `run_parcellation` for two variants on *both* trees, then scores them with `score_tree` and `summarize`. Verifies every metric is produced, the uncompressed reference gets its own row, across-domain rows use different fit/eval domains, and real data beats its own null on fidelity (mean delta 0.926). Synthetic and small deliberately: a GPT-2-scale integration run writes ~400 MB per matrix and exhausted the 16 GB local scratchpad at 9 GB, so the real integration happens on the cluster where the data already lives.
- 2026-09-09 -- [info/PARCELLATION_DESIGN.md](PARCELLATION_DESIGN.md) -- new **section 6, "How we decide whether a change is an improvement"**: the two metrics and why they are degenerate in opposite directions, the null calibration for both, the uncompressed reference and its caveat, the triviality checks, and the settled protocol choices (halves as samples 1,2 vs 3,4; block means on the fitting half; domains weighted equally; hard argmax as headline with soft reported alongside). Sections 6-11 renumbered to 7-12.

The 16 h wall-time request was padding against dataset streaming and proved unnecessary by a factor of ~48; the memory request was ~3x the actual peak, and the peak exceeded my 8.6 GB estimate because `take: 100000` documents materialize in RAM before tokenizing (the unfixed half of M7). **Revised guidance for a rerun at this scale: `-t 2 -m 24`.** One benign warning in the log: the tokenizer reports sequences longer than 1024 before `get_dataset` wraps them into `seq_len` chunks, so the model never sees an over-length input.

## Iteration 5 -- audit, two ceilings, and a stability finding (2026-09-09)

An audit of the Iteration 4 code against the agreed design found no correctness bugs in the metric math -- fidelity does not peek at the held-out matrix, and a test would catch it if it did -- but four things that would have bitten, plus a set of smaller inconsistencies. It also turned up an empirical result that matters more than any of them.

**The finding.** Measured on real wikitext connectivity (k=20, 3,000-unit subsample, 40 restarts), the two arms differ by nearly an order of magnitude in how reproducible their parcellations are across seeds *on identical data*:

| arm | ARI across seeds, same data | median max membership | units above 0.5 | networks each unit spreads over |
|---|---|---|---|---|
| `current` (binarize + PCA 200) | 0.096 | 0.20 | 1.6% | 11.5 of 20 |
| `nopca_fisher` | 0.741 | 0.53 | 51.6% | 4.1 of 20 |

Three consequences. First, raw cross-half reliability is **not comparable between arms** without dividing through by each arm's own noise floor -- an arm could look more reliable purely by having a quieter algorithm. That turned the reliability ceiling from a nice-to-have into a requirement. Second, the viability of a hard argmax label is **arm-dependent**: at a median max membership of 0.20 (uniform is 0.05) the `current` label is the top of a nearly flat noisy vector, while `nopca_fisher` puts half its units above 0.5. Third, `current` is *not* collapsing -- it uses all 20 clusters with the largest at 19-22%, so it produces a balanced partition that simply is not stable under discretization.

**Restart scaling and where the instability lives.** For `current`, going from 20 to 60 restarts roughly doubles hard ARI (0.063 -> 0.146), and at both budgets the *soft* consensus agrees 4-5x better than its argmax (0.303 and 0.457). So the underlying consensus is substantially more reproducible than the discrete labels derived from it. This is the mechanism behind the low peakedness, and it is the caveat attached to the decision to run 20 restarts: at that budget `current`'s reliability is not meaningfully distinguishable from zero, and the honest reading is "this pipeline does not produce a reproducible discrete parcellation at this budget" rather than "reliability is 0.06".

**Costs, measured rather than guessed.** At full scale (9,984 units, k=50): one k-means restart takes 44.5 s for the no-PCA arm and 6.2 s for the PCA arms. At the configured 100 restarts that is ~68 h serial for 42 matrices, which nobody had estimated and which would have been submitted under a 12 h wall clock. The nulls are exactly half of any such budget, and the across-domain (`avg`) matrices are a third of it. Both ceilings are free: the fidelity ceiling is one R2 between two matrices, and the reliability ceiling costs two Hungarian alignments, measured at 0.1% of the k-means time (0.04 s against 45 s).

## Iteration 6 -- first scored results, and what they show (2026-09-10)

Jobs 17356343 (split_halves + parcellation) and 17356344 (score) both completed clean: 1 h 39 m and 34 m, peak RSS 4.2 and 4.4 GB against 64/96 GB requested, 224 HDF5 files, 938 scored measurements. My wall-time estimate of ~14 h was out by 8.5x, because the earlier 44.5 s-per-restart timing was effectively single-threaded and the job ran on 16 cores.

**The connectome result replicates, and slightly exceeds, the poster.** Per-domain fidelity ceiling (R2 of half A predicting half B): agnews 0.985, bookcorpus 0.993, random 0.994, tldr17 0.978, wikitext 0.980, whitespace 1.000, codeparrot 0.749. For two symmetric noisy estimates of one truth, R2 = 2r - 1, so a ceiling of 0.98 implies a connectome correlation of about **0.99**, against the 0.974 Cory's poster reports. Higher as expected, since our halves are ~197k tokens against their 50k. Our between-domain figure, computed separately on `results/alldomains`, was 0.313 excluding whitespace against their 0.369. Both halves of their Result 1 reproduce.

**A bug in `fidelity_across`, now fixed.** Across-domain R2 came out at -11 to -13 for every arm and -118 for whitespace against agnews. The cause is scale, not structure: domains differ enormously in overall correlation magnitude (whitespace mean |r| 0.37, wikitext 0.047), so block means fitted on one domain are on the wrong scale for another and the residuals dwarf the variance. The ceiling itself was negative, which is the tell -- it is the raw matrix predicting the other raw matrix, with no parcellation involved. R2 asks whether the *values* transfer; the agreed question was whether the *structure* does. Now reported as Pearson r, which is scale-invariant. Demonstrated in the test suite: identical structure rescaled 8x and offset scores R2 = -597 and r = 1.000.

**The parcellations discard most of the reproducible structure.** Against a ceiling of ~0.98, held-out fidelity on genuine prose domains is 6-14%:

| domain | ceiling | current | legacy | nopca_fisher |
|---|---|---|---|---|
| wikitext | 0.980 | 0.078 | 0.057 | 0.140 |
| agnews | 0.985 | 0.071 | 0.063 | 0.109 |
| bookcorpus | 0.993 | 0.076 | 0.067 | 0.225 |
| tldr17 | 0.978 | 0.083 | 0.069 | 0.144 |
| random | 0.994 | 0.061 | 0.062 | 0.136 |
| codeparrot | 0.749 | 0.368 | 0.204 | 0.605 |
| whitespace | 1.000 | 0.647 | 0.217 | 0.747 |

The connectome is almost perfectly reproducible and the 50-cluster block model captures a tenth of it. Note also that the domain-averaged headline is inflated by whitespace and codeparrot, the two degenerate cases -- whitespace because everything correlates with everything, so a block model fits it trivially. Decision 2026-09-10: keep equal domain weighting for the average, and report per-domain values separately rather than reweighting.

**The null is clusterable, and that is the most consequential finding.** Reliability on circshift noise reaches 0.505 for `legacy` (0.73 on the random domain), often matching or beating the real data:

| arm | reliability_within real | null | delta |
|---|---|---|---|
| current | 0.127 | 0.045 | +0.082 |
| legacy | 0.451 | 0.505 | -0.054 |
| nopca_fisher | 0.621 | 0.487 | +0.134 |

Working hypothesis: circshift preserves each unit's autocorrelation, so units differ in effective sample size, hence in the magnitude of their noise correlations -- a stable per-unit property that k-means can cluster on. The triviality check corroborates from the real side: `nopca_fisher` scores **AMI 0.354 with hubness decile**, so the arm that won on stability is substantially grouping units by how strongly connected they are rather than by what they connect to. This is exactly the degenerate case the null and the triviality checks were built to expose, and they exposed it.

## Iteration 7 -- a silent no-op, and two decisive results (2026-09-10)

Job 17364074 completed in 2 h 20 m, exit 0, peak RSS 4.4 GB. 1,344 scored measurements.

**S10: `standardize_profiles` was accepted and silently ignored.** `run_parcellation` took the argument, never forwarded it to `sample_parcellations`, and so `vmf_profile` computed exactly `nopca_fisher` -- identical to three decimal places on all six metrics, which is how it was caught. Two failures compounded. The edit that added the forwarding used a search string with 16-space indentation where the code has 12 (a leftover from removing an `if True:` wrapper earlier), and that particular replacement had no assert, so it was a no-op. And the verification checked only `'standardize_profiles' in inspect.signature(run_parcellation).parameters`, which confirms the parameter exists and tests nothing about whether it reaches the clusterer. **FIXED**, `standardize_profiles` added to the provenance attrs (its absence there is why the output files gave no hint the setting had been dropped), and a structural test added that spies on the real `sample_parcellations` call and asserts every one of the nine parameters the two functions share actually arrives. That test is the general form of the fix; it would have caught this and will catch the next arm added the same way.

**The shortfall is the model class, not overfitting.** This is precisely what `fidelity_insample` was added to determine, and the answer is unambiguous. On prose domains (excluding the degenerate whitespace and codeparrot):

| arm | held-out | in-sample | ratio | uncompressed ceiling |
|---|---|---|---|---|
| current | 0.077 | 0.077 | 1.00 | 0.984 |
| legacy | 0.064 | 0.064 | 1.00 | 0.984 |
| nopca_fisher | 0.155 | 0.155 | 1.00 | 0.984 |

Held-out equals in-sample to two decimals: the partitions do not overfit their half **at all**. So the entire gap between 0.155 and 0.984 is the model form. A 50-cluster block model cannot describe this connectome however good the partition is, and improving the clustering cannot close it -- only changing the model class could. Whatever else this experiment concludes, that result stands on its own.

**The circshift null is not structureless, and the mechanism is identifiable.** The null fits a block model *better than real data does* -- in-sample 0.540 against 0.323 for `nopca_fisher`, and 0.310 against 0.111 for `legacy`. Working hypothesis: circshift preserves each unit's autocorrelation, so units differ in effective sample size and therefore in the magnitude of their noise correlations, making `R_null[i,j] ~ f(unit_i) * f(unit_j)` -- a rank-one hubness structure, which a block model captures well by grouping units on magnitude. This single mechanism accounts for the whole cluster of anomalies: the null being clusterable at all, its high in-sample fit, its high held-out fit, and `nopca_fisher` scoring AMI 0.354 with hubness decile on real data.

If that is right, the null is not "no structure" but "no structure beyond per-unit magnitude". That is arguably the *correct* null, but it is a far stronger baseline than intended and must be described that way rather than as a noise floor. `vmf_profile` removes per-unit magnitude by construction and is therefore the direct test -- and it is exactly the arm that did not run. Proposed cheap confirmation: leading-eigenvalue share of a null connectivity matrix, which under the hypothesis should be much larger than in the real matrix.

**`fidelity_across` is sane again** with Pearson r: ceiling 0.268 on real data rather than the previous -118. The null still exceeds real there (0.489 against 0.118 for `nopca_fisher`), consistent with the same rank-one story.

Job 17366628, commit `1e3df81`, 1,652 scored measurements in `results/reliability/metrics/scores.csv` (copied to [figures/scores.csv](../figures/scores.csv) for plotting). This is the first run in which every rung of the ladder exists, so a win can finally be attributed to a single change. Numbers below are means over the four prose domains (wikitext, agnews, bookcorpus, tldr17); whitespace and codeparrot are excluded from every average because a block model fits their degenerate connectivity almost perfectly and they dominate an equal-weighted mean.

| arm | reliability | rel. null | Δ rel | fidelity | fid. null | Δ fid | in-sample fid | null in-sample | AMI w/ hubness |
|---|---|---|---|---|---|---|---|---|---|
| legacy | 0.471 | 0.573 | **-0.102** | 0.064 | 0.315 | **-0.251** | 0.064 | 0.349 | 0.088 |

| vmf_profile | 0.514 | 0.289 | **+0.225** | 0.117 | 0.031 | **+0.087** | 0.118 | 0.054 | 0.100 |

Uncompressed reference (predicting R_B from R_A with no parcellation at all): 0.984.

**Finding 1: only `vmf_profile` beats its own null on both metrics.** Every other arm is either below its null on fidelity (all four) or below it on reliability as well (legacy, fisher_pca). Read without the null, `nopca_fisher` looks like the best arm by a wide margin -- reliability 0.698, double anything else, and the highest raw fidelity. Read against the null, it is the worst: its circular-shift control reaches 0.560 fidelity, so the parcellation is finding *less* block structure than the same pipeline finds in data with all cross-unit correlation destroyed. This is the single clearest argument in the project so far for having pre-registered a null at all; the raw ranking and the null-calibrated ranking disagree at the top.

**Finding 2: the confound is hubness, and the prediction recorded before the run was correct.** The pre-registered prediction (Iteration 7 edit log, 2026-09-10) was that if the null's clusterability is driven by per-unit magnitude, standardizing profiles should collapse it. It does: null in-sample fidelity falls 0.566 -> 0.054 from `nopca_fisher` to `vmf_profile`, a factor of ten, and AMI between the parcellation and hubness decile falls 0.300 -> 0.100 over the same step. The two quantities rise and fall together across all four rungs (0.035/0.173, 0.069/0.172, 0.300/0.566, 0.100/0.054), which is what identifies magnitude rather than something else as the thing the null was exploiting. A circular shift leaves each unit's variance and marginal intact, so any procedure that clusters partly on "how strongly connected is this unit" will find that structure survives the shift. Standardizing each row removes the magnitude and asks only about the pattern.

**Finding 3: `fisher_pca` isolates the cost of each change, and the answer is that neither change helps alone.** This is exactly why the arm was added. Dropping binarization with PCA held fixed (`current` -> `fisher_pca`) makes things *worse* on both null-calibrated metrics (Δ rel +0.070 -> -0.244, Δ fid -0.052 -> -0.085), because keeping the magnitudes without removing them again downstream is what lets hubness in. Dropping PCA on top of that (`fisher_pca` -> `nopca_fisher`) raises raw scores and raises the null by more. Only the third step, standardizing, converts the retained information into something the null cannot reproduce. The ladder's story is therefore not "each rung is an improvement" but "the first two rungs are only defensible as a pair with the third", which the one-change-per-rung design is what let us see.

**The shortfall is the model class, not overfitting -- now confirmed on all five arms.** Held-out and in-sample fidelity agree to two decimal places everywhere (0.064/0.064, 0.077/0.077, 0.062/0.061, 0.155/0.155, 0.117/0.118). A 50-block partition fit on half A predicts half B exactly as well as it predicts the half it was fit on. Nothing is being overfit; the gap from ~0.12 to the uncompressed 0.984 is entirely the block-model form. Raising 50 networks, or moving to a model class with more than one parameter per block pair, is the only direction that can close it.

**Caveat on the reliability ceiling.** The restart-split ceiling comes out *below* the split-half reliability for every arm (e.g. `nopca_fisher` 0.641 vs 0.698, `vmf_profile` 0.418 vs 0.514). This is not a contradiction, it is an artifact of how it is computed: the ceiling compares two 10-restart consensuses while reliability compares two 20-restart consensuses, and a consensus over fewer restarts is noisier. With restarts at 20 rather than 100 the ceiling is a pessimistic proxy, not a bound, and should not be plotted as one. Fixing it properly means either running the ceiling at 20 restarts per side (doubling the parcellation cost) or dropping it; deferred, not decided.

**Cross-domain generalization, null-calibrated: no arm survives it.** This is the 2x2's other half (`reliability_across`, `fidelity_across`) and it was not plotted in the Iteration 8 figures, which show only the within-domain split-half metrics. Restricted to the 12 ordered prose-domain pairs, and against the same circular-shift null:

| arm | rel. across | its null | Δ | fid. across (r) | its null | Δ |
|---|---|---|---|---|---|---|
| legacy | 0.254 | 0.503 | -0.249 | 0.208 | 0.535 | -0.327 |
| current | 0.035 | 0.064 | -0.029 | 0.207 | 0.323 | -0.116 |
| fisher_pca | 0.111 | 0.291 | -0.180 | 0.198 | 0.355 | -0.157 |
| nopca_fisher | 0.163 | 0.341 | -0.178 | 0.235 | 0.709 | -0.475 |

On cross-domain fidelity `vmf_profile` is at parity (+0.007, i.e. indistinguishable from the null) and every other arm is well below. A parcellation fit on wikitext carries essentially nothing about bookcorpus that a magnitude-matched null would not also carry. Either the parcellations are genuinely domain-specific, or 50 blocks is too coarse a description for the shared part to show through -- the uncompressed r of 0.531 says a shared part does exist.

## Decisions made

- 2026-09-08 (S1): knockout is **opt-in and per-network**. `run_knockout(networks=None)` is a no-op, so `-s all` never lesions a model by accident; `networks: all` or a list of indices builds one perturbed model per shared subnetwork, each writing to `<output_dir>/knockout/subnetwork<k>/`. The union-lesion the old OR-loop performed is no longer reachable — it could not answer what any single subnetwork contributes, which is the question the step exists to ask. Re-addable if a "remove all domain-general structure" experiment is ever wanted. Cost: one full connectivity run per selected network, so `networks: all` over 20 shared networks is 20x the baseline connectivity cost. Rejected alternative: per-network as the default (my initial recommendation) — Andrea preferred an explicit opt-in so no accidental lesioning is possible.
- 2026-09-08 (S1, ablation value): **mean-ablation by default**, `ablation: zero` retained as an option. Zero is off-distribution and conflates "network removed" with "input broken". The mean is taken **per domain**, read from the baseline run's cached `unit_means` for whichever domain is being processed, because a unit's mean activation differs substantially across domains (Iteration 1 diagnostics) and one global set of values would be off-distribution for most of them. Implemented by caching `unit_means`/`unit_stds` during the baseline connectivity run and adding `PerturbedModel.set_perturbation_values` to swap values between domains. Rejected alternatives: a single global mean (simpler, weaker rationale); computing means on the fly at knockout time (no baseline change, but roughly doubles forward passes on a step already N-times the baseline cost).
- 2026-09-08 (S1, controls): **deliberately deferred.** No size-matched or variance-matched random-lesion controls yet, so a deficit observed after a lesion is not yet interpretable on its own. `unit_stds` is cached now specifically so variance-matched controls can be built later without re-running the baseline. Note that the integration run already shows why this matters: network 0 covered 847 units and network 2 covered 2819, so comparing them directly is confounded by lesion size.
- 2026-09-08 (S3): knockout reads its own **`subnetwork_knockout`** config section, and `model_name` is **inherited from `connectivity`** and rejected if set under `subnetwork_knockout` — a lesioned run must use the same model as the baseline it is compared against. `seed` and `overwrite` are now forwarded. `run_knockout` also filters the connectivity section it passes through, so keys it controls itself cannot collide.
- 2026-09-07 (M8): chose **explicit invalidation plus merge-on-append**, rather than preserving the parcellation across a connectivity rewrite. Preserving it was the obvious reading of "fix the data loss" and is wrong: the parcellation is a function of the connectivity, so keeping it after a recompute yields a stale parcellation silently attached to a different matrix — a correctness bug that no log line would reveal, and worse than the loss it avoids. So the truncation stands, and `warn_dropped_keys` now names the discarded key, the file, and the remedy. Separately, `save_h5_data` gained `merge=True`, used by `run_parcellation` to write only the parcellation: appending a ~2 MB array previously rewrote the ~400 MB connectivity matrix and left a window in which a crash mid-write destroyed the connectivity as well. Also replaced a `load_h5_data` in `run_connectivity`'s cache check with the new metadata-only `h5_keys`, which had been reading the entire matrix to test for two keys. Rejected alternative: separating derived products into their own files (the cleanest design, since co-locating a derived product with its input under a truncating writer is the root cause, but it touches `run_parcellation`, `run_subnetwork_extraction` and all three plot functions — deferred).
- 2026-09-07 (S7, seeding scheme): chose **hierarchically derived sub-seeds** over a single global seed. A master `seed` in the config supplies the default for every step; each step derives sub-seeds from it via `util.derive_seed(seed, *keys)`, keyed by domain, by sample index, and by parcellated filename. Rationale: the pipeline caches to HDF5 and skips completed work, so re-running one domain or one file is a normal operation, and it must reproduce exactly what the full run produced for that unit. A single RNG stream would make each domain depend on how many draws preceded it. `derive_seed` uses hashlib rather than the builtin `hash()`, which is salted per process for strings. Within `sample_parcellations` a single `RandomState` is shared across the reductions and all clustering restarts, deliberately: reusing one fixed `random_state` for every restart would make all 100 restarts identical and destroy the consensus averaging, whereas drawing from one stream keeps them different *and* reproducible as a set. Verified: 12 of 12 restarts distinct within a run, and identical across runs. Rejected alternative: seeding only globally at process entry (simpler, but breaks single-domain re-runs).
- 2026-09-07 (M4): chose **option 3, restrict parcellation to `avg` files**, exposed as `parcellate_samples=False`. Cuts the longest stage to a fifth at `n_samples: 4`. Reversible without recomputing any model forward pass, because the per-sample connectivity HDF5s are cached; set `parcellate_samples: true` to recover them if parcellation stability becomes a claim.
- 2026-09-07 (M6): chose the **full reciprocal-best-match clique**. A network survives only if, for *every* pair of domains, the two networks assigned to it are each other's best match. The previous implementation chained matches along the alphabetically sorted domain list, verifying only `n_domains - 1` of the `n_domains * (n_domains - 1) / 2` pairs; that made the surviving set depend on domain *names* (sort position decided which domains were interior, load-bearing links) and let identity drift across hops, since the two ends of the chain were never compared. Also added an explicit `domains` argument to `run_subnetwork_extraction`, which is the mechanism for excluding the `random`/`whitespace` baselines from the definition of domain-generality; the Iteration 1 diagnostics give empirical support for excluding `whitespace` in particular. Rejected alternatives: a star topology against a designated reference domain (order-independent but privileges an arbitrary reference), and replacing the binary filter with a continuous cross-domain consistency score (more informative, and still the better long-run design, but deferred because the shared network is not a central claim of the current analysis).
- 2026-09-07 (S4 footing caveat, revisited): left as is. The final layer's connectivity is still computed on post-`ln_f` values while layers 0-11 are raw residual-stream values. Recorded here so it is not rediscovered as a bug; revisit if layer-12 behaves anomalously in the parcellation.
- 2026-09-03 (S4 fix): chose to map the final hidden-state index onto a wrapped `ln_f` (so the lesioned quantity is exactly the measured quantity) rather than dropping the final hidden state from the analysis. Rationale: preserves all 13 layers and all downstream shapes; the post-LN state is what downstream computation actually consumes. The alternative (excluding `hidden_states[-1]`, or re-deriving it pre-LN) remains on the table if the post-LN footing of layer 12's connectivity becomes a concern.
- 2026-09-03 (S5 fix): chose min-max-normalized inverse-inertia weights (`w = 1 - minmax(inertia)`, best sample → 1, worst → 0, all-equal degenerates to unweighted). Note: the worst sample now gets weight 0, i.e., is excluded when weighting is on. Alternatives (rank weights, softmax over −z(inertia)) not pursued for now.
- 2026-09-04 (dataset substitutions): `datasets` 4.x removed loading-script support, which killed two of the five text domains outright. Replacements chosen empirically rather than by reputation:
  - **bookcorpus** -> `rojagtap/bookcorpus`. Verified to be a faithful parquet mirror: its first streamed row is byte-identical to the original `bookcorpus` ("the half-ling book one in the fall of igneeria series ..."), same sentence-level `text` field. `SamuelYang/bookcorpus` returns the same row and is an equally good fallback.
  - **tldr17** -> `dim/tldr_17_50k`. Preserves the original webis schema (`body`/`content`/`summary`), so `get_dataset`'s content-key autodetection still selects `content` (the post body) as before. **Caveat for the paper: this is a 50,000-post subset of the ~4M-post `webis/tldr-17`, not the whole corpus.** At the default budget (400k tokens/domain) the subset is far more than sufficient, but the tldr17 domain is now sampled from a smaller pool than the other domains, and `shuffle` operates over the whole 50k rather than over a sample of millions. Revisit if a properly mirrored full tldr-17 appears on the Hub.
  - **wikitext** -> `Salesforce/wikitext` (same data, namespaced id; bare repo ids are no longer valid).
  Alternatives considered and rejected: `lucadiliello/bookcorpusopen` (BookCorpusOpen is a *different, larger* corpus with document-level rather than sentence-level segmentation — not a drop-in); pinning `datasets<4` (would freeze the project on an unmaintained release to preserve two dataset loaders).
- 2026-09-04 (cluster job generation): chose **versioned YAML cluster profiles** (`configs/cluster/*.yml`) over a `--preamble` file of raw shell lines for supplying cluster-specific settings to `make_jobs.py`. Rationale: the profile is committed alongside the code, so a run is reproducible from the repository alone and the SC setup is self-documenting; a preamble file would have been more flexible but would have pushed the cluster knowledge into an untracked file. Precedence is CLI flag > profile > built-in default, so profiles act as baselines and one-off deviations stay on the command line.
- 2026-09-04 (partition assignment): chose to **split the pipeline across partitions by step** rather than run everything in one GPU allocation. `connectivity` and `subnetwork_knockout` are GPU-bound and go to `jag-standard` (a6000); `parcellation`, `subnetwork_extraction` and the `plot_*` steps are sklearn/CPU workloads and go to `john` (CPU-only). Rationale: the clustering stage (MiniBatchKMeans x100 plus Hungarian alignment) is likely the longest wall-clock stage and would otherwise hold a contended GPU idle throughout. Costless because `/juice6` is mounted cluster-wide and the pipeline already caches to HDF5 between steps.
- 2026-09-03: verification tests live in `tests/` as runnable scripts (no pytest infra yet); run with `PYTHONPATH=. python tests/verify_iter0_fixes.py` from the repo root in the `analysis` env.

- 2026-09-08 -- [info/PARCELLATION_DESIGN.md](PARCELLATION_DESIGN.md) -- **decision 2.1 settled: keep `|r|`.** Rationale (Andrea): in fMRI a deactivation is a physical event with a direction, so sign is interpretable and task-negative structure is a finding; a residual-stream dimension has no comparable privileged direction, so its sign is closer to a coordinate convention and an anticorrelation between two units does not carry that interpretive weight. Taking `|r|` makes the analysis invariant to the convention. Limitation recorded rather than fixed: the method cannot distinguish co-activation from reciprocal trade-off, and the signed matrix is preserved on disk if a later claim needs it. Stage 1 of the recommendation, Stage 3's SBM weight description, and the open-decisions list were all amended for consistency. Also rewrote 2.3 (PCA truncation and whitening) in plain terms: PCA compresses the *columns* of the unit-by-connection table, not the rows, so units are never transformed and the parcellation is not in a rotated unit space -- what changes is the description used to judge similarity between units, with truncation (54.7% of variance dropped) and whitening (0.074%-variance direction weighted equally with the 2.8% one) as the two consequences.

## Cluster

Compute for this project runs on the Stanford SC cluster (NLP group, CLiMB lab). Connection, storage layout, SLURM conventions, cluster profiles and job-launching instructions are in [CLUSTER.md](CLUSTER.md).

Code moves to the cluster by git (so every result traces to a commit hash) and results come back by rsync through the `scdt` data-transfer node. A full run is two submissions: `connectivity` on a GPU partition, then the clustering and plotting steps on a CPU partition.
