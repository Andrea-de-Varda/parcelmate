# parcelmate — project log

This is the running record of everything done to this codebase: project structure, all issues found, every design decision, and a dated log of every edit. It exists so that the eventual paper's methods section can be reconstructed exactly. Update it whenever anything changes. (Kept separate from README.md, which belongs to the upstream repo; merge relevant parts there later if desired.)

## What the project does

parcelmate applies the methodology of fMRI functional connectivity analysis to the internals of a language model. Each hidden unit of an LLM (a single dimension of the residual stream at a given layer boundary) is treated as a voxel; its "timecourse" is its activation across tokens of naturalistic text. The pipeline: (1) **connectivity** — run a HuggingFace model (default GPT-2) over text from several domains (wikitext, bookcorpus, agnews, tldr17, codeparrot, plus `random` and `whitespace` baselines), extract per-unit timecourses, and compute the unit-by-unit Pearson correlation matrix, averaged (Fisher-z) over 4 independent ~100k-token samples; (2) **parcellation** — binarize the absolute connectivity at each unit's 90th percentile, PCA to 200 components, run MiniBatchKMeans (k=50) 100 times, align the runs with the Hungarian algorithm, and average into a soft parcellation (unit × network membership probabilities); (3) **subnetwork extraction** — keep networks that are reciprocal best matches across all domains (chained in alphabetical domain order) and average them into a "shared" (domain-general) parcellation; (4) **knockout** — clamp the units belonging to shared subnetworks to zero via `PerturbedModel`/`PerturbedLayer` wrappers and re-run the connectivity pipeline on the lesioned model; (5) **plots** — connectivity clustermaps, network heatmaps, and stability analyses (correlations of connectivity matrices across samples and domains). Everything is cached as HDF5 under `results/`, driven by `python -m parcelmate.bin.main <config.yml> -s <steps>`; `parcelmate/bin/make_jobs.py` generates SLURM scripts.

Code map: [parcelmate/model.py](../parcelmate/model.py) (pipeline + perturbation machinery), [parcelmate/data.py](../parcelmate/data.py) (datasets, tokenization, filtering, correlation), [parcelmate/plot.py](../parcelmate/plot.py), [parcelmate/util.py](../parcelmate/util.py) (HDF5 I/O), [parcelmate/cfg.py](../parcelmate/cfg.py) (YAML config), [parcelmate/constants.py](../parcelmate/constants.py), [parcelmate/bin/main.py](../parcelmate/bin/main.py) (CLI driver).

## Iteration 1 — basis and thread diagnostics (2026-09-07)

Run on the seven-domain `results/alldomains` connectivity matrices (GPT-2, local verification run) before committing to any downstream analysis. Motivation: the residual stream accumulates, `x_{l+1} = x_l + \Delta_l`, so unit *(l, j)* and unit *(l+1, j)* share content by construction. If cross-layer connectivity were dominated by this persistence, the parcellation would be recovering "residual threads" (one dimension tracked through depth) rather than functional networks. There is no brain analogue; it is purely architectural.

**Per-edge, the confound is large.** Mean |r| between the same dimension at adjacent layers, versus different dimensions at adjacent layers:

| domain | same *j* | different *j* | ratio | percentile rank of same-*j* |
|---|---|---|---|---|
| wikitext | 0.867 | 0.051 | 17.0 | 0.996 |
| agnews | 0.866 | 0.048 | 18.2 | 0.997 |
| tldr17 | 0.868 | 0.050 | 17.4 | 0.996 |
| bookcorpus | 0.863 | 0.069 | 12.6 | 0.993 |
| random | 0.894 | 0.053 | 16.9 | 0.998 |
| codeparrot | 0.849 | 0.168 | 5.0 | 0.974 |
| whitespace | 0.737 | 0.406 | 1.8 | 0.859 |

For a given unit, its correlation with its own dimension one layer up exceeds ~99.6% of its correlations with every other dimension one layer up.

**But it does not dominate the clustering signal, because threads are numerically tiny.** The parcellation clusters on a top-10% binarized fingerprint, which selects ~999 partners out of 9,983, while a unit has only 12 same-dimension thread-mates. Measured on wikitext:

| quantity | value |
|---|---|
| thread-mates captured in the top 10% | 11.17 of 12 (93.1%) |
| units capturing all 12 thread-mates | 54.4% |
| threads as a share of selected partners | 1.1% (11 of 999) |
| share of total \|r\| mass on same-dimension pairs | 1.50% (chance 0.12%, so 12x enriched) |

So the thread is almost always fully inside the fingerprint, and it is enriched an order of magnitude over chance, but 99% of the clustering signal comes from different-dimension partners. **Conclusion: the confound is real and must be reported, but it is not a reason to abandon the residual-stream unit definition or to switch to block writes (\Delta) now.** The planned rotation null (see Iteration 2) remains the decisive test, and its two-null variant (shared vs. per-layer rotation) will quantify the thread contribution directly.

**Side findings from the same diagnostic.** Off-diagonal correlation distributions differ qualitatively across domains:

| domain | kurtosis | mean \|r\| | p99 \|r\| |
|---|---|---|---|
| agnews | 25.9 | 0.044 | 0.156 |
| random | 22.5 | 0.050 | 0.177 |
| tldr17 | 22.2 | 0.046 | 0.167 |
| wikitext | 20.2 | 0.047 | 0.170 |
| bookcorpus | 6.5 | 0.065 | 0.235 |
| codeparrot | 0.3 | 0.160 | 0.549 |
| whitespace | -0.8 | 0.373 | 0.915 |

Three things follow. First, `whitespace` is **degenerate**, not merely different: mean |r| is 0.37 and the distribution is platykurtic, meaning nearly everything correlates with nearly everything. This is independent empirical support for excluding it from the domain-general criterion (M6). Second, `codeparrot` is a genuine intermediate case and should not be assumed comparable to the prose domains. Third, `random` is statistically indistinguishable from the prose domains (kurtosis 22.5, mean 0.050), which is direct empirical confirmation of **S6**: the decode/re-encode round trip leaves the "random" baseline far more language-like than uniform random token ids would be.

## Decisions made

- 2026-09-07 (M8): chose **explicit invalidation plus merge-on-append**, rather than preserving the parcellation across a connectivity rewrite. Preserving it was the obvious reading of "fix the data loss" and is wrong: the parcellation is a function of the connectivity, so keeping it after a recompute yields a stale parcellation silently attached to a different matrix — a correctness bug that no log line would reveal, and worse than the loss it avoids. So the truncation stands, and `warn_dropped_keys` now names the discarded key, the file, and the remedy. Separately, `save_h5_data` gained `merge=True`, used by `run_parcellation` to write only the parcellation: appending a ~2 MB array previously rewrote the ~400 MB connectivity matrix and left a window in which a crash mid-write destroyed the connectivity as well. Also replaced a `load_h5_data` in `run_connectivity`'s cache check with the new metadata-only `h5_keys`, which had been reading the entire matrix to test for two keys. Rejected alternative: separating derived products into their own files (the cleanest design, since co-locating a derived product with its input under a truncating writer is the root cause, but it touches `run_parcellation`, `run_subnetwork_extraction` and all three plot functions — deferred).
- 2026-09-07 (S7, seeding scheme): chose **hierarchically derived sub-seeds** over a single global seed. A master `seed` in the config supplies the default for every step; each step derives sub-seeds from it via `util.derive_seed(seed, *keys)`, keyed by domain, by sample index, and by parcellated filename. Rationale: the pipeline caches to HDF5 and skips completed work, so re-running one domain or one file is a normal operation, and it must reproduce exactly what the full run produced for that unit. A single RNG stream would make each domain depend on how many draws preceded it. `derive_seed` uses hashlib rather than the builtin `hash()`, which is salted per process for strings. Within `sample_parcellations` a single `RandomState` is shared across the reductions and all clustering restarts, deliberately: reusing one fixed `random_state` for every restart would make all 100 restarts identical and destroy the consensus averaging, whereas drawing from one stream keeps them different *and* reproducible as a set. Verified: 12 of 12 restarts distinct within a run, and identical across runs. Rejected alternative: seeding only globally at process entry (simpler, but breaks single-domain re-runs).
- 2026-09-07 (M4): chose **option 3, restrict parcellation to `avg` files**, exposed as `parcellate_samples=False`. Cuts the longest stage to a fifth at `n_samples: 4`. Reversible without recomputing any model forward pass, because the per-sample connectivity HDF5s are cached; set `parcellate_samples: true` to recover them if parcellation stability becomes a claim.
- 2026-09-07 (M6): chose the **full reciprocal-best-match clique**. A network survives only if, for *every* pair of domains, the two networks assigned to it are each other's best match. The previous implementation chained matches along the alphabetically sorted domain list, verifying only `n_domains - 1` of the `n_domains * (n_domains - 1) / 2` pairs; that made the surviving set depend on domain *names* (sort position decided which domains were interior, load-bearing links) and let identity drift across hops, since the two ends of the chain were never compared. Also added an explicit `domains` argument to `run_subnetwork_extraction`, which is the mechanism for excluding the `random`/`whitespace` baselines from the definition of domain-generality; the Iteration 1 diagnostics give empirical support for excluding `whitespace` in particular. Rejected alternatives: a star topology against a designated reference domain (order-independent but privileges an arbitrary reference), and replacing the binary filter with a continuous cross-domain consistency score (more informative, and still the better long-run design, but deferred because the shared network is not a central claim of the current analysis).
- 2026-09-07 (S4 footing caveat, revisited): left as is. The final layer's connectivity is still computed on post-`ln_f` values while layers 0-11 are raw residual-stream values. Recorded here so it is not rediscovered as a bug; revisit if layer-12 behaves anomalously in the parcellation.
- 2026-09-03 (S4 fix): chose to map the final hidden-state index onto a wrapped `ln_f` (so the lesioned quantity is exactly the measured quantity) rather than dropping the final hidden state from the analysis. Rationale: preserves all 13 layers and all downstream shapes; the post-LN state is what downstream computation actually consumes. The alternative (excluding `hidden_states[-1]`, or re-deriving it pre-LN) remains on the table if the post-LN footing of layer 12's connectivity becomes a concern.
- 2026-09-03 (S5 fix): chose min-max-normalized inverse-inertia weights (`w = 1 - minmax(inertia)`, best sample → 1, worst → 0, all-equal degenerates to unweighted). Note: the worst sample now gets weight 0, i.e., is excluded when weighting is on. Alternatives (rank weights, softmax over −z(inertia)) not pursued for now.
- 2026-09-04 (dataset substitutions): `datasets` 4.x removed loading-script support, which killed two of the five text domains outright. Replacements chosen empirically rather than by reputation:
  - **bookcorpus** -> `rojagtap/bookcorpus`. Verified to be a faithful parquet mirror: its first streamed row is byte-identical to the original `bookcorpus` ("the half-ling book one in the fall of igneeria series ..."), same sentence-level `text` field. `SamuelYang/bookcorpus` returns the same row and is an equally good fallback.
  - **tldr17** -> `dim/tldr_17_50k`. Preserves the original webis schema (`body`/`content`/`summary`), so `get_dataset`'s content-key autodetection still selects `content` (the post body) as before. **Caveat for the paper: this is a 50,000-post subset of the ~4M-post `webis/tldr-17`, not the whole corpus.** At the default budget (400k tokens/domain) the subset is far more than sufficient, but the tldr17 domain is now sampled from a smaller pool than the other domains, and `shuffle` operates over the whole 50k rather than over a sample of millions. Revisit if a properly mirrored full tldr-17 appears on the Hub.
  - **wikitext** -> `Salesforce/wikitext` (same data, namespaced id; bare repo ids are no longer valid).
  Alternatives considered and rejected: `lucadiliello/bookcorpusopen` (BookCorpusOpen is a *different, larger* corpus with document-level rather than sentence-level segmentation — not a drop-in); pinning `datasets<4` (would freeze the project on an unmaintained release to preserve two dataset loaders).
- 2026-09-04 (cluster job generation): chose **versioned YAML cluster profiles** (`configs/cluster/*.yml`) over a `--preamble` file of raw shell lines for supplying cluster-specific settings to `make_jobs.py`. Rationale: the profile is committed alongside the code, so a run is reproducible from the repository alone and the SC setup is self-documenting; a preamble file would have been more flexible but would have pushed the cluster knowledge into an untracked file. Precedence is CLI flag > profile > built-in default, so profiles act as baselines and one-off deviations stay on the command line.
- 2026-09-04 (partition assignment): chose to **split the pipeline across partitions by step** rather than run everything in one GPU allocation. `connectivity` and `subnetwork_knockout` are GPU-bound and go to `jag-standard` (a6000); `parcellation`, `subnetwork_extraction` and the `plot_*` steps are sklearn/CPU workloads and go to `john` (CPU-only). Rationale: the clustering stage (MiniBatchKMeans x100 plus Hungarian alignment) is likely the longest wall-clock stage and would otherwise hold a contended GPU idle throughout. Costless because `/juice6` is mounted cluster-wide and the pipeline already caches to HDF5 between steps.
- 2026-09-03: verification tests live in `tests/` as runnable scripts (no pytest infra yet); run with `PYTHONPATH=. python tests/verify_iter0_fixes.py` from the repo root in the `analysis` env.

## Cluster

Compute for this project runs on the Stanford SC cluster (NLP group, CLiMB lab). Connection, storage layout, SLURM conventions, cluster profiles and job-launching instructions are in [CLUSTER.md](CLUSTER.md).

Code moves to the cluster by git (so every result traces to a commit hash) and results come back by rsync through the `scdt` data-transfer node. A full run is two submissions: `connectivity` on a GPU partition, then the clustering and plotting steps on a CPU partition.
